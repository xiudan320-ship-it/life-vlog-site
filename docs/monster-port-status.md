## 闭环进度

原生 `recover-first-battle.py` 已执行第一关战前准备，确认玩家入场回满生命、敌人基础表先转整数后调整。`recover-first-battle-actions.py` 在合成固定随机输入下执行原版行动选择、攻击、HP、回合结束及胜负分支；玩家攻击三次获胜，生命剩余 230。动画回调按命中顺序排空，这不是动画时序或完整 APK 运行验证。

`recover-first-credit.py` 继续执行原结算的经验/金币发放片段：该样本奖励金币 117、经验 15、无物品，得到金币 1117、等级 1、巅峰 1、经验 15、生命 230。成就/任务回调仍被捕获，不代表其已持久化。`recover-first-material-drops.py` 另用原物品工厂和原合并函数验证首关材料构造，覆盖有/无掉落及重复材料。

仓库组合测试已串起新档 → 原目录生成敌人及品质/难度调整 → 自行选择出手、命中、换敌和胜负 → 原品质倍率奖励与材料掉落 → 入账和关卡进度 → 装备核心属性重算 → 本地保存重读。原来的预录命中顺序测试已替换，调度不再把原生 trace 当输入。页面和控制器现已接入这一限定路径。本地格式是迁移版 JSON，不冒充 Android 存档兼容。

`recover-solo-normal-battles.py` 比较 15 次完整原生战斗，覆盖 1–3 个敌人、胜利/失败、秒杀、暴击和持续未命中，并比较完整 HP、死亡/行动标记、波次、阶段及核心随机消耗。标题彩票和 UI 随机被排除在核心随机输入之外，不能宣称全局随机序列或视觉行为一致。原版换敌保留已有玩家行动标记，可能由新敌人先行动；该规则已经保留。

`recover-copy-progress.py` 验证 576 组章节进度和 16 个计数边界，包括新章节给予 10 money、终章完成标记与重复进度键只更新首项。`getSaveMd5` 原代码在 0x85e9b4 调用属性重算；36 组真实初始装备/翅膀收集样本确认重算不回血。

首关测试页可新建角色、自动战斗、查看初始九件装备/翅膀及材料，并保存后刷新继续。固定验证输入下首胜为金币 1117、经验 15、HP 230；第二胜后金币 1234、等级 2、经验 10，攻击和最大生命均为 259。另一组输入覆盖实际材料入包及重载。

`recover-war-view.py` 执行原版战斗 UI 装配指令，以渲染工厂/节点属性适配器记录 19 个节点在 640×960 和 640×1280 下的位置、锚点、颜色及关系，生成 `war-view.json`。这不是原生图形运行或逐像素对照。视口按原 `AppDelegate` 的 640×960、EXACT_FIT/FIXED_WIDTH 选择适配；主页等级取 `text_level`，结算图片和缩放顺序按原 `WarFinishLayer::initUi` 恢复。

当前每次普通攻击间隔及伤害飘字仍为测试表现，随机输入使用 WebCrypto 提供 31 位数值；不承诺原全局随机序列或动画一致。特殊遭遇会明确停止并保留进度，不替换成普通狼。页面目前只开放首关，其他入口未开放。下一步需要补齐特殊遭遇、地图/其他关卡、技能、宠物、Buff 全生命周期、随机装备、任务/成就、深渊、试炼和平台桥接；不能宣称全游戏 100% 一致。

- `node scripts/check-syntax.mjs`：206 个 JavaScript 文件通过。
- `pnpm run build`、构建/资源预算、静态/UI/结构/CSS 门禁通过；首关游戏资源未进入首页预缓存。
- `pnpm run test:monster-browser` 和 `node tests/monster-browser.mjs --webkit`：Chromium/WebKit 首关、续玩、升级、材料、保存错误与重试、损坏存档保留、特殊遭遇边界、浅/深色、减少动态效果和六个宽度通过。内容安全策略保留现有脚本限制；本地 HTTP fixture 仅移除传输用 `upgrade-insecure-requests`，生产头未削弱。自动化 WebKit 不等同于真实 iPhone 验收。

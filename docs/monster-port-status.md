# 黑暗传说 7.1 移植试玩

目标是在当前 App 的快捷滑动条内逐步恢复原版玩法，供 iPhone 浏览器运行。本页描述当前源码，未发布的变化见 CHANGELOG 的 Unreleased，部署提交与门禁以 CHANGELOG 为准。尚未完成全游戏或原版 100% 一致交付。

## 原版依据

- APK：`com.zn.monster`，7.1 / versionCode 55，SHA-256 `9767B9C3945D38985C07DB73D56DEC83E162B37C69A9686686BC9BDE67E35079`。
- 原实现为 Cocos2d-x 3.4 / 32 位 ARM，核心逻辑在 `libcocos2dcpp.so`；APK 不能直接在 iOS 执行。当前是原资源与恢复规则的浏览器移植，没有生成原生 iOS 安装包。
- 原生证据来自 Unicorn 2.1.4 对原 ARM 函数的限定执行，使用确定性合成输入；平台、图形及部分副作用有明确适配边界，不代表已运行完整 APK 或完成逐像素比对。
- 全 22 份目录、84 份 UI 布局及原图片/音频已解析；运行时只使用已接通资源。解析目录位于 `C:/Users/xiuda/Downloads/monster-analysis`。早期压缩导出不作为当前部署依据。

按用户要求新增战败收益保留规则，此处有意区别于原版：地图按已击杀敌人的数量、品质与既有掉落公式结算；副本等一次性结算模式的金币、经验和常规掉率按击杀比例分配。未击杀怪物不发奖励；战败不发荣誉、首通掉率保底、章节/通关/深渊里程碑奖励，也不解锁下一关。特殊遭遇仅在该怪物确实被击杀时计入。获胜路径的原生数值和随机消耗保持不变。结算失败保留未保存状态并阻止新战斗，重试仅保存现有结果，不再抽奖或重复入账。

## 模块与存档契约

- `entry.js` 装配宿主认证、原目录、引擎、视图与控制器；没有登录时不载入引擎。
- `achievement-domain.js` / `achievement-view.js` 读取 119 条成就和 72 条称号：只统计已接通的战斗、培养和任务等条件，达标自动发原表积分和魔石；部分付费称号使用移植版积分门槛。称号属性参与前台和离线角色重算；依赖未实现玩法的条件明确标记。累计事件自本功能上线开始，等级和已有装备可根据当前状态初始化。
- `equipment-target-domain.js` / `equipment-target-view.js` 跟踪全部徽章、四类特殊徽章、翅膀与无法打造但可掉落的高品质装备；`state.equipmentTargets` 保存目标，已知来源按实际表列出并定位。`bag-sort-domain.js` 用装备 `acquisitionOrder` 和背包序号排序，新装备的 `inventory.acquisitionSequence` 在掉落／打造／熔炼时递增；历史获取顺序不可追溯。`bag-batch-domain.js` 在分解前一次校验选择、锁定与返还上限。
- `copy-drops-domain.js` 从实际共享结算掉落池生成关卡预览；`result-loot-view.js` 展示全部结算物品，`item-detail-view.js` 展示背包库存和实际换装后的属性差值。
- `copy-domain.js` / `encounter-domain.js` 恢复准备与遭遇；`copy-selection-view.js` 提供选关；`adventure-domain.js` 负责门票、掉落、奖励及进度。
- `offline-domain.js` / `offline-runner.js` / `monster-offline-worker.js` / `offline-view.js` 实现单独开启、领取和客户端模拟；以账号云档保存关卡、难度、波数、服务器开始时间与随机种子，领取前重新获取服务器时间及核对 revision，结果与结束记录同次保存。复用既有战斗、任务、奖励和战败部分结算，离线战败后自动重试并展示次数；每次进入付费关卡扣除卷轴，卷轴不足或接近存档 1 MiB 上限时提前停止。连续战斗与此玩法是不同路径，客户端 Worker 计算不是服务端防作弊。
- `port-drop-domain.js` 除十种配方徽章外，为可识别的付费商店／兑换物品及 VIP 翅膀补充掉落，并为七种兑换宠物添加难度 3、积分 2000 起的试炼奖励池；目录装配后供战斗及获取途径共同使用。补充掉落和概率是移植平衡，不声称来自原版。原版深渊每日重置未接通，但已通关的深渊层当前可重复挑战并获得奖励。
- `shop-domain.js` / `shop-view.js` 使用 APK 商店表中的 22 个已接通用途的魔石商品包，保留原包数量及价格；金币商品直接入账，其余材料按 ID 堆叠。余额、金币或材料在同一账号版本保存，失败后先重试现有结果；离线挂机期间禁止购买。金币接近 20 亿上限时展示实际入账量，到上限时禁止购买，这是避免浪费魔石的移植版保护。材料来源弹窗可定位可购买商品；未接通用途及第二类商品暂不出售。
- `trial-domain.js` / `trial-view.js` 提供三档试炼的续层、积分、纪录及领奖。积分先抽层数倍率、再抽基础值，额外加分词条按原浮点乘 1.1、单层封顶 500；奖励按原表行难度计算权重，选完后装备单独评分并按模式 7 生成神器。宠物奖励保存持有记录，可在 35 级后选为主宠或副宠。
- `pet-domain.js` / `pet-view.js` 恢复 26 种目录宠物的初始属性、一只主宠及最多四只副宠的核心属性贡献。`partyRole` 标记跟随每条持有记录，区分同 ID 宠物；主副宠切换、角色重算与云档同次保存。副宠按原生 float32 顺序乘 0.3 和忠诚系数，82 组副宠原生样本覆盖 26 种工厂及多宠组合；主宠另有 353 组贡献样本。角色属性从装备与宠物原始来源重建，不重复叠加；星级与成长参与计算，宠物独立行动仍未接通。
- `pet-progression-domain.js` 按原生 `Pet::addExp` 的逐级余量更新已分配的宠物，1–59 级阈值为 `15000 × level²`，到 60 级保存经验 52,215,000。角色升级递归产生的每次经验事件均按顺序应用；每只副宠获得每次主宠对应事件的原生 30% 截断值，装备 tag 42 加成按原 float32 顺序生效。战斗、任务及用户指定的战败部分经验共用同次云档入账，失败重试不重发；未选中的同种宠物保持各自进度。
- `pet-care-domain.js` 对照 372 组原生忠诚样本：胜利累计击败 600 只使主宠忠诚下降 1，副宠为 1800 只，最低 30；战败不计忠诚击杀。主副宠切换保留计数，并按新身份阈值处理下一次胜利。每个宠物精魂可恢复 1 点忠诚，支持一键补满和缺料来源；同种宠物分别记录忠诚与计数，角色属性随战斗／喂养立即重算。与物品及奖励同次账号保存，失败重试不重复消耗或结算。
- `pet-battle-domain.js` 使用原宠物工厂词条和 `Pet::getSkillPro`：35 级起依次为主宠和副宠的每条可用词条抽一次 0–100；星级、忠诚、身份与装备 tag 43 影响阈值，副宠按原 float32 乘 0.3。第三条仅品质 5 可触发。本场临时增伤、免伤、奖励等效果供前台、离线 Worker 和胜利／战败收益结算使用，不写入常驻角色属性。宠物详情显示概率及锁定条件，战斗顶部显示触发数量；尚无独立攻击。
- `pet-training-domain.js` / `pet-training-view.js` 按持有记录选择培养目标和未出战材料：同种且品质不高于目标的宠物可融合升星；品质 4 的目标可吞噬不高于自身品质的宠物，成长满 100 升为品质 5。原生星级阈值为 1／2／4／6，最高 4 星；成长最高 100，超出部分不保留。融合花费 100 或 300 魔石，吞噬品质 4 花费 90 魔石；预览展示结果、材料、费用并要求确认。材料删除、扣款、角色属性重算和账号保存同次处理，失败重试原结果；云档校验星级、经验和成长边界。
- `task-domain.js` / `task-view.js` 使用 `task.json` 的 161 条任务（普通 154、固定日常 7）。普通任务候选 ID <= 499，等级范围为 `max(0, level - 13)` 至 `min(80, level + 2)`；超过 10 条时按原拒绝重抽选出不重复的 10 条。任务板首次打开建立 `state.taskBoard`（`dailyRewardDay / points / entries`）；每日领取重抽并清空进度，保留积分。指定关卡的击杀和副本任务可跳转并定位地图；尚未解锁的位置只可查看，挑战条件不变。固定击杀、副本、遭遇和材料条件可进度或交纳；固定击杀覆盖所有战斗类型，击杀与副本日常的相近等级条件均为角色等级减关卡等级不超过 5。战败计已击杀怪，副本战败不计完成。地图击杀计数包括已击杀的追加遭遇敌人；原胜利结算片段将敌人向量长度传给地图任务，但该片段本身不能独立证明所有遭遇场景的完整行为。领取与扣料同次保存，失败重试不重抽。
- `upgrade-domain.js` / `smith-view.js` 提供背包及已穿戴普通装备的强化、评分重铸和金币／魔石附魔。按用户要求，普通装备换装交换强化等级，较高值保留给穿戴装备，附魔／评分／词条各自保留；强化上限 +30，失败扣料但保级。+0–18 数值保留原生对照，+19–30 的成本／概率／属性倍率及返还是自定义扩展，不声称来自 APK。现有 +5 配方装备材料规则继续生效；打造对比预览穿戴后继承强化的范围。
- `copy-scout-domain.js` / `copy-scout-view.js` 显示关卡推荐值和实际常规怪物属性范围、技能、首通／难度／波数条件；主页、角色和选关显示参考战力，每章怪物以三列一屏展示，波数可加减或选择。点按挑战，长按或详情按钮查看对比，锁定地图可只读查看。战力是自定义启发参考，未预测胜率，地图随机遭遇不包含在区间内；随机遭遇目录不能独立挑战。侦察不消耗游戏随机数、资源或云档版本。
- `god-upgrade-domain.js` / `god-upgrade-view.js` 实现神器升星与洗星：每件最多升星两次，升星直接成功；洗星只能在升星后替换末星，第二次升星须确认。工厂生成的 `attributes` 尾部 `godLevel` 项按顺序保存神器词条，升星次数存 `godUpgradeCount`。本 App 旧物品缺少该字段时确实从未经过此功能，首次操作从零计数；原 Android 档不导入。成本、词条抽取及拒绝重抽由有限原生样本验证。
- `craft-domain.js` / `craft-view.js` 读取 126 行 `make.json`：双列配方显示名称与等级，分类间保留选择，装备分类默认定位不高于角色等级的最高等级配方；徽章展示当前角色下的实际属性及未接通效果。普通成品以金币、特殊徽章以魔石支付；配方中的装备材料须恰好强化 +5，消耗后成品入背包，装备评分按已有生成规则随机。`special-upgrade-domain.js` / `special-upgrade-view.js` 用 `7000 + 品质 × 10 + 下一强化等级` 查徽章升级配方，消耗金币及材料固定升级至多 +5；这些配方键不是打造商品。
- `smelt-domain.js` / `smelt-view.js` 选择背包内未穿戴、未锁定且等级高于玩家等级减 15 的神器装备，按数量、属性和装备评分计算成功率与产物品质，成功获得铁匠徽章；失败也扣材料与金币。材料熔炼仅使用高品质且标记可熔炼的材料，每 10 个为一组，以原确认动作固定加成计算能量之源与余数概率。
- 物品 6911–6914 是冒险者、深渊、铁匠、巅峰徽章，分别按 subtype 11–14 穿戴并收集属性，同 subtype 替换；按装备等级检查，不以 `paragonGrowth` 作为穿戴门槛。原新档标记经原生函数核实为 `tutorialFlags`，不是宝石槽，也不代表镶嵌玩法已经接通。
- 试炼 `state.trial` 首次进入时建立，包含 `hard / level / score / status / bestScores / rewards`；状态为 `ready`（待挑战本层）、`ended`（战败待领奖）或 `claimed`（本轮已入账）。逐层保存；结束领奖与背包入账在同一个账号版本写入，失败重试仅保存现有结果，不重新抽奖。页面刷新恢复已结算层；进行中的单场仍按既有战斗边界处理。
- `battle-domain.js` / `skill-domain.js` 使用既有攻击、目标、生命与属性领域模块推进战斗，旧 `solo-battle-domain.js` 已删除。
- `item-domain.js` / `gem-domain.js` / `paragon-equipment-domain.js` 构造物品；`loadout-domain.js` 管理穿戴和技能装配；视图与领域逻辑分离。
- `bag-item-domain.js` / `bag-item-view.js` 恢复道具出售、装备分解及锁定。道具按 `useid === 6` 发魔石，其余金币；库存不超过 9 时仅逐件卖出，超过时可选数量。分解按普通、特殊及徽章分支发金币／神器碎片和强化返还，5115 组原生数值样本覆盖评分档、附魔、品质、星数及强化边界。移除物品与返还同次保存；失败后在背包内重试，不能重复结算。
- `character-view.js` / `visual-ui.js` 复用原装备格、面板、勇者与物品/技能图标，提供纸娃娃装备位、背包格子、技能图标卡片和物品详情。地图展示原章节缩略图及可点击怪物节点，其他模式为敌人图片卡片。菜单、主页、战斗和结算保留 Canvas 原图，奖励物品也显示原图图标；有实际意义的数值、名称和提示仍使用文字。
- 结算画面返回刚选的关卡；`copy-selection-view.js` 保留类别、章节及章节栏位置，明确的主页按钮仍返回主页。
- `save-store.js` / `save-state.js` 管理云存档；Worker `monster-save-api.js` 提供 `GET/PUT /api/monster/save`，GET 含服务器当前时间。D1 `monster_saves` 每个 user_id 一条记录，原子 revision 防止多设备覆盖；不接受客户端传入账号归属，同家庭账号也不能读取其他人的档。
- 存档失败会保留当前未保存状态并阻止新战斗；401 需返回登录、409 需重载、网络错误可重试。请求前后检查账号和 token，迟到响应不能恢复旧账号状态。
- 首页不提前加载游戏资源，游戏页面、模块、样式与原资源不进入宿主预缓存。此版本仍需联网，不提供完整离线安装。

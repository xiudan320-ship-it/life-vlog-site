# 心情瓶高保真复刻、缓慢重播与大趋势图 V2 规划

> 状态：实现完成，正在进行本地门禁验证；未部署。本文件的实施记录见文末。
>
> 编写日期：2026-09-01
>
> 参考：用户提供的浅色手绘心情瓶与趋势图截图，以及当前生产环境深色页面截图。
>
> 关系：本方案承接 `mood-month-visual-remediation-plan.md` 已完成的基础定位、裁切和可见性修复，并覆盖其中关于瓶体外观、动画节奏与手机趋势尺寸的旧目标。

## 1. 本轮要解决的问题

当前实现已经能把表情放入罐体、在进入视口时触发动画并显示趋势，但体验仍与参考图存在明显距离：

1. 表情落入速度过快，8 条记录几乎一闪而过，没有“逐个落入、慢慢装满”的观感。
2. 瓶子轮廓仍偏工程化：罐身偏矮、肩部和瓶口比例不自然、缺少参考图的椭圆口沿、暖色玻璃、圆润底座和手绘双线层次。
3. 动画只自动播放一次，用户无法主动再次欣赏。
4. 手机趋势图把 720×260 的坐标系整体压缩，轴标签、表情标尺、线和点都太小。
5. 当前实际记录集中在月底，按整月 1～31 日比例绘制后，数据全部挤在最右侧；即使图表容器变高，趋势仍会显得局促。

本轮目标：

- 以用户提供的参考图为视觉基准，高保真重绘一个纵向、圆润、手绘质感的玻璃瓶；
- 当月表情以明显可见但不拖沓的节奏依次落入并稳定堆叠；
- 点击或键盘激活整只瓶子，可从头重播当前月份全部表情；
- 手机趋势图占据足够高度，文字、标尺、点和线清楚可读；
- 稀疏月份自动使用“有记录日期展开”布局，避免所有数据挤在月底一角。

## 2. 非目标与约束

- 不复制参考应用的品牌文字、头像、专属插画或水印；只复刻瓶子的构图、比例、手绘层次和交互体验。
- 继续使用本项目已有 16 张圆形/方形心情 PNG。
- 不引入 Chart.js、D3、GSAP、物理引擎或 Canvas 游戏循环。
- 不增加数据库表、Worker API、migration、兼容层或 `app.js` 业务逻辑。
- 不使用真实账户、token 或业务数据做自动化验收。
- 页面仍需支持深色/浅色主题、375px 手机、横屏、130% 字号和 `prefers-reduced-motion`。

## 3. 瓶子高保真视觉规格

### 3.1 整体比例

当前 320×360 的罐体过矮。V2 改为纵向 `viewBox="0 0 360 440"`，目标可见轮廓宽高比约 0.70～0.76，接近参考图的高瓶身。

手机端目标显示：

- 宽度：容器可用宽度的 82%～90%，最大约 340px；
- 高度：约 390～430px，按 `360 / 440` 比例自然缩放；
- 水平严格居中；
- 上下预留 12～20px 呼吸空间；
- 不因表情数量改变瓶体尺寸，避免 CLS。

### 3.2 几何锚点

所有 path、裁切区和动画罐口坐标必须来自同一组常量：

| 部位 | V2 坐标目标 | 视觉要求 |
| --- | --- | --- |
| 瓶口中心 | `(180, 52)` | 动画统一入口 |
| 外口沿 | `x=92～268, y=25～78` | 宽椭圆、双层口沿 |
| 内口沿 | `x=108～252, y=38～60` | 暖灰内圈，不像矩形盖子 |
| 瓶颈 | `x=108～252, y=66～102` | 短而平滑 |
| 肩部 | 从 `(108,84)` 平滑扩至 `(55,145)` | 左右对称、无硬折角 |
| 主罐身 | `x≈48～312, y≈140～372` | 侧壁略鼓、下部圆润 |
| 罐底 | `y≈372～414` | 椭圆双线底座，与瓶身同轴 |
| 内腔安全区 | `x≈72～288, y≈105～374` | 所有表情最终四角均不得越界 |

SVG 的瓶口、罐身和底座屏幕中心误差不得超过 2px；左右轮廓在同一 y 高度的宽度差不得出现肉眼可见偏斜。

### 3.3 参考图层次

图层固定为：

1. 罐体暖色透明底：浅色主题使用米白/暖灰低透明度，深色主题使用略亮于卡片的暖灰绿透明层；
2. 罐口后沿；
3. 罐内表情裁切层；
4. 罐身主轮廓；
5. 罐口前沿；
6. 左上大面积柔和高光；
7. 左侧弧形高光；
8. 椭圆双线底座。

主轮廓使用 2.5～3.5px 圆头圆角线条；高光更细、更透明。不得使用发光描边、重阴影或规则矩形瓶盖。

### 3.4 手绘感实现

- 通过两条略有差异但稳定的 Bézier path 形成手绘双线感；不使用每次刷新变化的随机噪声。
- 可为外轮廓加入非常轻微的固定曲率不对称，但中心线和整体轮廓必须稳定。
- 不使用高成本 SVG turbulence 动画；如使用静态滤镜，必须验证移动 Safari 性能和深色主题边缘清晰度。
- 参考图的暖色内腔和白色高光可以复刻，但不得直接把整张参考截图作为背景。

### 3.5 表情尺寸与堆叠

- 1～12 条：表情目标 30～36px，保持疏朗；
- 13～31 条：目标 26～32px；
- 32～62 条：目标 22～28px，允许克制重叠；
- 成员 1 始终方形，成员 2 始终圆形；
- 堆叠从底部开始，日期较早的记录在下，较新的记录在上；
- 同一输入的最终坐标、旋转和缩放必须完全确定；
- 表情可以轻微相互覆盖，但不能全部堆成一团，也不能穿过内壁、瓶口或底座。

## 4. 缓慢落入动画

### 4.1 节奏目标

以当前常见的 8 条记录为验收基准：

- 单枚时长：950～1150ms；
- 相邻素材起始间隔：140～180ms；
- 第 1 枚到第 8 枚全部稳定：约 2.0～2.5 秒；
- 用户应能清楚看到“从瓶口进入 → 向下加速 → 碰到堆叠区域 → 轻微回弹 → 停稳”五个阶段；
- 不得再使用约 480ms 的快速坠落；
- 不使用无限弹跳、持续漂浮或强烈旋转。

### 4.2 数量自适应

不能让 62 枚按 160ms 排队十秒。使用确定性分组：

| 数量 | 每批数量 | 批次间隔 | 单枚时长 | 目标总时长 |
| --- | --- | --- | --- | --- |
| 1～12 | 1 | 140～180ms | 950～1150ms | 1.0～2.8s |
| 13～31 | 2 | 110～140ms | 900～1050ms | ≤3.0s |
| 32～62 | 3～4 | 80～110ms | 850～1000ms | ≤3.2s |

同一批内可有 20～40ms 微小错峰，避免完全同步。顺序仍由日期、席位和 ID 决定。

### 4.3 路径与落地

1. 所有素材从内口沿中心附近出现，初始透明度 0、缩放约 0.78。
2. 每枚素材依据最终槽位计算独立 `dx/dy`，只动画内层 `.mood-jar-motion` 的 transform 和 opacity。
3. 下落前 70% 使用加速曲线；接近槽位时轻微压缩至约 0.94；随后回弹到 1.03；最后稳定为 1。
4. 旋转变化控制在约 8～14°，不能像卡片翻转。
5. 动画结束后取消动画对象并显式写回最终 inline state，避免 fill mode 残留。
6. 动画期间瓶体、卡片高度和后续内容位置不得变化。

### 4.4 首次自动播放

- 仍使用“数据已准备好 + 瓶体至少 35% 进入视口”双条件。
- 首次自动播放每次进入心情路由、每个月份各执行一次。
- 在瓶体位于屏幕外时不得提前启动。
- 切换月份会取消旧动画、渲染新数据，等新瓶体进入视口后播放。
- 缓存和云端数据二次确认不得把首次动画误判为编辑动画。

## 5. 点击瓶子重新播放

### 5.1 交互载体

将整个瓶子舞台改成原生 `<button type="button">` 或在其外层使用覆盖整个瓶子的原生按钮。优先直接使用 button，内部只有装饰 SVG 和不可交互表情，不存在嵌套控件问题。

按钮要求：

- `aria-label="重新播放本月心情落入瓶子的动画"`；
- 保留至少 44×44px 的触控面积，实际为整只瓶子；
- Tab 可聚焦，Enter/Space 可重播；
- `:focus-visible` 使用清晰但不破坏瓶体轮廓的外圈；
- `:active` 只提供轻微透明度/边线反馈，不缩放整瓶导致布局抖动；
- 瓶子下方显示简短提示：“点击瓶子可重新播放”。

### 5.2 重播状态机

```text
settled -- click/Enter/Space --> cancelling --> prepared --> replaying --> settled
replaying -- click/Enter/Space --> cancelling --> prepared --> replaying
```

- 重播始终针对当前月份当前完整 `jarSignature`，不重新请求网络。
- 重播前取消所有旧 animation，逐枚恢复到罐口预备状态，然后在下一帧统一开始。
- 动画播放中再次点击：立即取消旧序列并从第一枚重新开始，不叠加第二组动画。
- 重播不改变月份、滚动位置、焦点或趋势图状态。
- 保存/删除正在发生时，以最新 canonical 月份数据为准；旧 signature 的重播回调不得写回 DOM。
- 重播完成后通过现有 polite 状态区播报一次“本月 8 条心情已重新落入瓶中”，不能逐枚播报。

### 5.3 Reduced motion

`prefers-reduced-motion: reduce` 下：

- 瓶子仍可聚焦，避免功能突然消失；
- 点击后不做位移/回弹，直接确认当前最终状态；
- polite 状态提示“已显示本月心情；系统已启用减少动态效果”；
- 测试必须确认 `getAnimations().length === 0`。

## 6. 手机趋势图放大重构

### 6.1 当前问题

当前 SVG 内部固定 720×260，手机只把整张图缩小到约 330px 宽。12px 内部字号实际显示约 5～6px；三档标尺、日期、线和点都过小。真实记录仅出现在 28～31 日时，数据又集中在横轴末端，所以视觉上只剩右侧一小撮折线。

### 6.2 双布局坐标系

把单一 `TREND_LAYOUT` 改为纯函数 `getTrendLayout({ compact, distinctDays, daySpan })`：

桌面/平板：

- `viewBox: 0 0 720 320`；
- plot 左右约 88/24；
- 三档 y 间距至少 82；
- 内部文字 14～16；
- 点直径 12～14，透明命中区 44。

手机 ≤700px：

- `viewBox: 0 0 390 360`；
- 图表 CSS 高度约 300～340px，不再是约 120px 的扁图；
- plot 左右约 68/16；
- 三档 y 约 72/180/288；
- 纵轴表情 28～32px，文字至少 14px；
- 日期标签至少 13px；
- 数据线 3.5～4px；
- 可见点直径 14～16px；
- tooltip 正文至少 14px、行高 ≥1.5。

CSS 不允许再次把 390×360 画布按 720×260 的比例压扁。

### 6.3 稀疏月份展开模式

在手机端满足任一条件时启用 `recorded-days` 模式：

- 当月不同记录日期 ≤8；
- 或所有记录日期跨度 ≤10 天且前方/后方存在大段空白。

该模式：

- 只为真实有记录的日期分配 x 槽位，并在 plot 宽度内等距展开；
- 横轴显示真实“28日、29日、30日、31日”等标签；
- 不创建缺失日期的数据点；
- 图表上方或摘要中显示“本月记录较少，按有记录日期展开”；
- 无记录跨度仍用弱化虚线表示，tooltip 显示真实日期；
- 屏幕阅读器摘要明确说明当前为等距展示，避免误解为真实时间间隔。

当不同记录日期 >8 或日期覆盖范围较广时，继续使用完整 1～月末的比例时间轴。

桌面默认保留完整月份时间轴；如记录极少，也可使用同一展开模式，但必须保持说明一致。

### 6.4 图例与点选

- 图例紧贴图表上方，昵称、线型、方/圆点形不得缩小到难以辨认。
- 两位成员使用颜色 + 实/虚系列 + 方/圆点形；跨未记录日期的桥线使用更细的点状虚线和较低透明度。
- 点击/触摸点显示完整日期、昵称、真实心情和三档状态。
- HTML 命中按钮与 SVG 点使用同一布局模型，屏幕位置误差不得超过 2px。
- 避免同一数据点产生两个 Tab 停靠点：SVG 可见点负责绘制和指针，HTML overlay button 负责键盘/触控语义，或反过来，但只能保留一套键盘焦点。

## 7. 模块设计

### 7.1 `modules/mood-month-summary-domain.js`

- 保持罐槽位、数量分组和趋势数据为纯逻辑；
- 增加确定性 animation batch 元数据，或提供独立纯函数计算批次；
- 增加趋势 x 轴模式判定与真实日期槽位模型；
- 不访问 DOM、matchMedia、IntersectionObserver 或动画 API。

### 7.2 `modules/mood-month-summary-view.js`

- 使用新的瓶口常量和 360×440 几何；
- 区分 `auto-enter`、`replay`、`mutation-enter`、`edit`、`remove` 五种动画原因；
- 提供 `replayJar()`，负责取消、准备、下一帧开始和完成播报；
- 使用动态 trend layout 渲染 axis/path/point/overlay；
- route 离开时取消动画、observer、requestAnimationFrame 和完成回调。

### 7.3 `modules/mood-diary-view.js`

- 绑定瓶子 button 的 `replay-jar` action；
- 不在普通 click 委托中误把趋势点或其他区域当成瓶子重播；
- 把重播动作交给月度 summary view，不交给 controller 重新请求数据。

### 7.4 模板与样式

- `modules/routes/templates/mood-diary.html`：替换瓶子 SVG path、将舞台改为可访问按钮、增加重播提示、补充 trend layout 所需语义。
- `styles/mood-diary.css`：新瓶体比例、主题色、focus/active、表情密度档、手机高趋势图、tooltip 和安全区。
- 不把业务逻辑塞入 `app.js`。

## 8. 实施阶段

### 阶段 A：建立视觉基线

1. 用 390×844 深色页面复现当前瓶子与小趋势。
2. 保存参考瓶、当前瓶和目标 wireframe 的尺寸记录。
3. 新增会失败的断言：瓶体比例、口沿椭圆、慢动画时长、重播次数、手机趋势高度与稀疏日期展开宽度。

### 阶段 B：高保真瓶子

1. 建立 360×440 单一坐标系和几何常量。
2. 重绘罐体填充、双层口沿、圆肩、鼓腹、双线底座和高光。
3. 重建内腔裁切与槽位边界。
4. 在 0、1、8、31、62 条记录下先验收静态画面。

### 阶段 C：慢动画和重播

1. 实现数量自适应批次和 950～1150ms 单枚轨迹。
2. 保留首次进入视口自动播放。
3. 将瓶体改为原生按钮并实现 replay 状态机。
4. 完成播放中再次点击、快速切月、mutation、route 离开和 reduced-motion。

### 阶段 D：大趋势图

1. 把固定布局重构为手机/桌面动态布局函数。
2. 手机采用 390×360 高画布和更大文字/点/线。
3. 增加稀疏月份 `recorded-days` 展开模式和可读说明。
4. 对齐 SVG 点与 HTML 命中区，去除重复键盘焦点。

### 阶段 E：门禁和发布

1. 运行完整测试和构建。
2. 固定预览站录制或截图首次下落、点击重播和趋势交互。
3. 真机/等效 WebKit 验证 390px 深色页面。
4. 主线程审计通过后再上线，不由实现线程自行发布。

## 9. 自动化测试计划

### 9.1 Domain

- 1、8、12、13、31、32、62 条记录的批次、延迟和总时长均在规定范围。
- 同一输入每次得到相同批次与槽位。
- 新瓶安全区内所有表情四角不越界。
- 4 天月底记录触发 recorded-days 模式，并生成四个等距真实日期槽位。
- 超过 8 个不同日期切回完整月份比例轴。
- 原始日期和 mood 不被展示模型修改。

### 9.2 Browser/UI

- 390×844 下瓶体屏幕高宽比处于目标区间，口沿/罐身/底座中心误差 ≤2px。
- 8 枚动画单枚 duration ≥950ms，起始 delay 不相同，最后稳定时间约 2.0～2.5s。
- 屏幕外动画调用为 0，进入 35% 后开始。
- 动画结束点击瓶子，动画调用数增加 8；再次点击会取消旧动画且活动动画总数不翻倍。
- Enter/Space 重播，焦点始终留在瓶子按钮。
- reduced-motion 点击后动画数仍为 0，并出现相应状态文本。
- 手机趋势 SVG 实际高度 ≥300px，内部字号计算后 ≥13px，线宽 ≥3.5px，可见点 ≥14px。
- 4 个月底日期的点横向覆盖 plot 宽度至少 70%，不能挤在最右 15%。
- SVG 点和命中按钮中心误差 ≤2px，命中区 ≥44×44px。
- 每个趋势点只有一个键盘 Tab 停靠点。
- 375、390、430px、844×390、768×1024、1440×900 无横向溢出。

### 9.3 视觉截图

至少保存并人工检查：

- 浅色空瓶；
- 深色 8 枚稳定瓶；
- 8 枚动画中间态；
- 62 枚满瓶；

截图测试不能只判断 PNG 字节数；至少结合 bbox、像素非空区域或稳定视觉快照，确保不是截到空卡片。

## 10. 人工验收脚本

1. 打开心情页并停留在月历，确认瓶子未在屏幕外偷偷播放。
2. 滑到瓶子，确认 8 枚表情用约 2 秒依次从椭圆瓶口慢慢落入。

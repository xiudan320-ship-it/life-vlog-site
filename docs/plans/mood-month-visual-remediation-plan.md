## 1. 背景与目标

当前月度数据、最多心情统计和文字摘要能够读取，但核心可视化没有达到交付目标：

1. 当用户滑动到“本月心情罐”时，看不到当月表情从罐口落入瓶中的过程。
2. 表情素材出现在罐体左上方或罐外，没有按照计算出的槽位堆叠。
3. 罐口、瓶颈、罐身和底座的 SVG 轮廓存在错位，整体不像一个完整、居中的玻璃罐。
4. “心情趋势”有图例、摘要和明细，但实际折线区域没有显示。
5. 现有浏览器测试只确认节点和数据存在，没有验证用户是否真的看得到瓶、表情和趋势线，因此错误通过了发布门禁。

本轮目标不是继续增加新功能，而是把已经承诺的核心体验做成真实可见、可重复验证的端到端闭环：

- 罐体几何完整且不偏移；
- 表情最终全部位于罐内；
- 只有当罐体进入视口时才播放一次下落动画；
- 趋势图在 iPhone Safari、Android Chrome 和桌面浏览器中真实可见；
- 自动化测试从“DOM 中有节点”升级为“节点具备正确可视几何”。

## 2. 已确认的问题与测试缺口

### 2.1 表情最终位置没有应用到布局

`modules/mood-month-summary-view.js` 已为每枚表情写入 `--jar-x`、`--jar-y`、`--jar-rotation` 和 `--jar-scale`。当前 `.mood-jar-item` 只读取旋转与缩放，没有把 `--jar-x`、`--jar-y` 映射到 `left`、`top`。

结果是领域层算出的安全槽位没有真正作用于 DOM。绝对定位元素停留在静态起点，截图中因此只看到一枚素材挤在卡片左上角，其他素材也可能重叠在同一位置。

现有测试只读取元素 style 中的自定义变量并判断数值范围，没有读取 `getBoundingClientRect()`，所以“变量正确但元素位置错误”仍会通过。

### 2.2 动画触发时机与用户视线脱节

当前动画由月份数据 render 原因触发。进入心情页面后，数据会在用户仍位于月历区域时完成加载，位于下方的心情罐即使播放过动画，用户也看不到。用户之后滑到瓶子，只能看到动画结束后的静态状态。

后续必须把“数据已准备好”和“罐体已经进入视口”拆成两个条件，不能再把网络请求完成等同于动画可播放。

### 2.3 当前下落路径没有从真实罐口到达目标槽位

现有动画只改变表情节点自身百分比 transform；它既没有读取罐口中心，也没有根据每个最终槽位计算起点位移。即使补上 `left/top`，也可能表现为素材在原位置附近移动，而不是从罐口落下。

后续需要一次性读取罐体尺寸，以罐口中心为统一起点，通过 transform 位移到每枚素材的最终槽位。不得在每一帧读取布局。

### 2.4 罐体 SVG 各层缺少统一几何契约

当前罐身、罐口、反光和底座是几条独立 path，缺少明确的内壁、安全区和锚点定义。截图可见罐口与瓶颈分离、线条重叠或不居中；表情层也没有与瓶体内腔共享裁切边界。

后续必须先确定统一 `viewBox` 和几何基准，再绘制各层，不能靠逐条 path 目测修补。

### 2.5 趋势图测试只验证 DOM，不验证绘制结果

现有测试主要检查：

- `hidden === false`；
- SVG 中存在趋势点；
- 存在若干 path；
- 摘要和明细有文字。

这些断言无法发现以下问题：

- SVG 实际高度为 0 或可见区域被压缩；
- path 的 `getTotalLength()` 为 0；
- stroke/fill 在当前浏览器中解析为透明或无效；
- 点和线落在 viewBox 外；
- 图表被其他层覆盖；
- 真实数据日期不连续时只生成孤立点，没有形成用户可识别的趋势。

## 3. 完成后的体验定义

### 3.1 页面进入与滚动

1. 页面先正常显示完整月历，不等待动画。
2. 月度数据准备完成后，瓶子显示完整轮廓，但待播放表情保持不可见或停在罐口上方的预备状态。
3. 当心情罐至少约 35% 进入视口时，触发本月首次下落动画。
4. 同一个月份、同一批数据在本次路由停留期间只完整播放一次。
5. 用户向上滑走再滑回来，不重复播放整罐动画。
6. 切换月份后，新月份拥有独立的一次播放机会；不能沿用上个月的已播放标记。
7. 从历史列表返回月度页时，恢复原滚动位置，不因动画强制滚到瓶子。

### 3.2 八条记录的目标效果

以用户截图中的 8 条记录为基准：

- 8 枚素材均从罐口中心附近进入；
- 按日期、席位稳定排序，每批相隔约 45～70ms；
- 单枚落下约 480～650ms，带一次克制的压缩/回弹；
- 整体在约 900～1300ms 内结束；
- 先落下的素材停在更低槽位，后落下的素材堆在上方；
- 动画结束后刷新页面或重新 render，最终位置完全一致；
- 动画期间页面仍可滚动和点击，不设置阻塞层。

### 3.3 保存、编辑和删除

- 保存新增心情：如果罐体正在视口内，只让新增素材从罐口落下；如果罐体不在视口内，记录为待播放，用户滑到罐体时再播放新增素材。
- 编辑已有心情：保留槽位，素材短暂交叉淡化为新心情，不重放整罐下落。
- 删除心情：目标素材快速淡出，剩余素材用短位移动画压实；退出时长短于进入时长。
- 云端重新读取失败：保留已成功写入的本地结果和最终位置，显示同步警告，不清空瓶子。

### 3.4 减弱动画

当 `prefers-reduced-motion: reduce` 生效时：

- 不执行滚动触发下落、回弹、压实位移或折线绘制动画；
- 表情直接出现在最终槽位；
- 趋势图立即显示最终线与点；
- 数据、按钮、提示和明细功能保持完整。

## 4. 玻璃罐几何重建方案

### 4.1 单一坐标系

继续使用项目内原生 SVG，不引入外部瓶子图片或物理引擎。罐体固定使用 `viewBox="0 0 320 360"`，并定义以下几何锚点：

| 区域 | 目标范围 | 用途 |
| --- | --- | --- |
| 罐口中心 | `(160, 42)` | 所有下落素材的视觉起点 |
| 罐口内宽 | `104～216` | 限制进入路径，不穿过瓶盖边缘 |
| 内腔顶部 | `y ≈ 78` | 从瓶颈过渡到罐身 |
| 内腔左右安全边界 | `x ≈ 64～256` | 表情最终槽位边界 |
| 内腔底部 | `y ≈ 320` | 最底层素材中心不得越过 |
| 底座中心 | `x = 160` | 校验底座与罐身是否同轴 |

罐口、瓶颈、罐身、底座、高光必须围绕同一中心线绘制。罐口左右差、罐身左右差、底座左右差在最终 SVG 中均不得超过 1px。

### 4.2 图层顺序

从后到前固定为：

1. 玻璃内腔浅色底；
2. 罐内表情裁切层；
3. 罐身边线与底座；
4. 罐口前沿；
5. 高光。

罐口后沿应位于表情后方，前沿位于表情前方，才能产生“素材进入瓶中”的遮挡关系。不能让一整块不透明 SVG 覆盖表情，也不能让表情浮在所有边线之上。

### 4.3 内腔裁切

新增明确的 `.mood-jar-viewport` 容器，所有表情放入该容器。容器必须使用与 SVG 内腔一致的裁切轮廓：

- 首选 CSS `clip-path: polygon(...)` 加圆角/椭圆底部组合，覆盖当前目标浏览器；
- 如 Safari 对组合裁切表现不稳定，则将表情作为 SVG `<image>` 渲染并复用同一个 `<clipPath>`；
- 不接受只设置 `overflow: visible` 后依赖罐身边线遮掩；
- 裁切区至少比可见边线向内缩 6～10px，避免旋转素材穿墙；
- 62 枚上限下所有素材中心和四角都必须位于裁切区内。

### 4.4 最终定位

为 `.mood-jar-item` 补齐最终位置契约：

```css
.mood-jar-item {
  left: var(--jar-x);
  top: var(--jar-y);
  transform: translate(-50%, -50%) rotate(var(--jar-rotation)) scale(var(--jar-scale));
}
```

领域层继续输出确定性百分比坐标，但需要根据新的内腔安全区重新校准最小/最大 x、y。测试不能只检查变量值，必须检查屏幕实际矩形。

## 5. 视口触发动画方案

### 5.1 状态机

`modules/mood-month-summary-view.js` 维护纯视图级状态，不把动画状态塞入业务数据：

```text
waiting-data -> waiting-viewport -> playing -> settled
                      |                |
                      | reduced motion |
                      +--------------> settled
```

每个状态以 `monthKey + jarSignature` 标识。月份变化或记录集合变化时生成新 key；普通 render 不重置状态。

### 5.2 IntersectionObserver

- 观察 `#moodJarStage`，建议 `threshold: 0.35`，并用轻微负 bottom `rootMargin` 避免刚露出一条边就播放。
- 数据未准备好时只记录“已经进入视口”；数据随后到达应立即播放。
- 数据先到、罐体后进入时保持待播放状态。
- 不支持 `IntersectionObserver` 的环境：若罐体当前在视口则播放，否则直接显示最终状态，禁止无限等待或轮询 scroll。
- route 离开时 disconnect observer、取消现有 animation，并把所有节点设置到明确最终状态。
- 页面从后台恢复时不重放已完成动画。

### 5.3 动画实现

采用“最终槽位定位 + 内层素材 transform 动画”：

1. 外层 `.mood-jar-item` 始终固定在最终 `left/top`，保证布局真值稳定。
2. 一次读取罐体矩形，计算罐口中心到每个槽位的 `dx/dy`。
3. 只动画内层素材的 `translate3d/rotate/scale/opacity`。
4. 关键帧包括：罐口预备、加速下落、轻微压缩、一次回弹、稳定。
5. 不动画 `top/left/width/height`，不在帧循环中调用 `getBoundingClientRect()`。
6. 记录较多时分批并行，最大 stagger 窗口封顶，62 枚也不得播放数秒钟的长队列。
7. 任意新 render、月份切换或路由离开都先 cancel 旧动画，再显式写入新最终状态，不能依赖 `onfinish` 保证正确性。

## 6. 趋势图修复方案

### 6.1 先保证画布真实可见

- SVG 同时设置 `viewBox="0 0 720 260"`、`width="720"`、`height="260"` 和 `preserveAspectRatio="xMidYMid meet"`。
- CSS 使用明确的 `aspect-ratio: 720 / 260; width: 100%; min-height: 0;`，手机端不得依赖 `height:auto + min-height` 的浏览器推断组合。
- 数据存在时先批量生成 axis/path/point，再移除 `hidden`；空态时明确隐藏 SVG 并显示指导文字。
- 图表 shell 保留尺寸，不被绝对定位的 tooltip/键盘辅助按钮撑开或覆盖。
- 为 stroke/fill 提供 CSS 变量与 SVG 属性双重 fallback，避免移动 Safari 对 SVG 自定义属性解析异常时整条线透明。

### 6.2 让真实记录形成可理解的趋势

每位成员按日期排序：

- 连续日期之间用实线连接；
- 中间缺少记录时，用低强调虚线桥接两个真实观测点，并在图例/说明中标明“虚线跨过未记录日期”；
- 不为缺失日期新增数据点，不计算或显示虚假的心情值；
- 只有一个数据点时仍显示至少 10px 的方形/圆形可见点；
- 两位成员继续使用颜色 + 实/虚系列样式 + 方/圆点形区分，不能只靠红蓝颜色。

这样既能符合用户对“趋势曲线”的直观预期，也不会把缺失日期伪装成已记录数据。

### 6.3 手机端交互

- 可见点半径约 5～6px，但透明触控命中区至少 44×44px。
- 点击点显示日期、昵称、真实心情和高涨/平稳/低落分档。
- tooltip 保持在图表卡片内，根据点位选择左上或右上，不能超出手机视口。
- 键盘 Tab 可聚焦每个数据点；Enter/Space 展开信息，Escape 关闭。
- 保留文本摘要与按日明细，图表不作为唯一信息来源。

### 6.4 可选入场动画

趋势图首先必须静态可见。只有静态渲染和跨浏览器验收通过后，才加入 350～550ms 的线条描绘与点淡入；同样由趋势区首次进入视口触发，并遵守 reduced-motion。趋势动画不得与罐子动画争抢主线程。

## 8. 实施顺序

### 阶段 A：建立失败复现

1. 用 8 条确定性当月记录复现用户截图。
2. 在 390×844、iPhone Safari 等效环境记录罐体、每枚素材和 SVG 图表的 bounding box。
3. 新增当前实现必然失败的断言：素材中心在罐内、趋势画布高度大于 0、至少一个可见点和一条可见线。
4. 保存修复前截图，作为视觉对照，不使用真实账号数据。

### 阶段 B：修复罐体几何和静态堆叠

1. 重绘统一坐标系的罐口、罐身、底座和高光。
2. 增加内腔裁切层和正确图层顺序。
3. 将 `--jar-x/y` 应用到 `left/top`。
4. 先关闭所有动画，验证 1、8、31、62 枚素材的静态位置全部正确。

### 阶段 C：实现滚动触发下落

1. 增加 IntersectionObserver 与月份级一次性状态。
2. 计算罐口到最终槽位的 transform 路径。
3. 完成首次/月切换整罐动画和 mutation 单项动画。
4. 完成取消、快速切月、后台恢复及 reduced-motion 降级。

### 阶段 D：修复趋势图

1. 固定 SVG 尺寸和响应式比例。
2. 验证 axis、line、point 的实际 bbox、stroke 和 viewBox 坐标。
3. 增加缺失日期虚线桥接，使稀疏记录仍形成可理解趋势。
4. 验证点选、键盘、tooltip、摘要和按日明细。
5. 静态正确后再决定是否启用趋势入场动画。

### 阶段 E：真实视觉门禁与发布

1. 跑全量 fixture、构建预算、CSS 覆盖和浏览器回归。
2. 固定预览站用手机尺寸截取：罐体未触发、动画中间态、动画结束态、趋势图。
3. 对比浅色/深色、正常/130% 字号、竖屏/横屏、normal/reduced motion。
4. 预览通过后才发布生产；生产再次执行 CORS、Axe 和 release smoke。

## 9. 自动化验收标准

### 9.1 罐体静态几何

- `#moodJarStage` 宽高比稳定且宽度不超过视口。
- 罐口中心、罐身中心和底座中心的屏幕 x 坐标误差不超过 2px。
- 每枚 `.mood-jar-item` 的 bbox 宽高大于 0。
- 每枚素材中心位于内腔 bbox 内，四角不穿出裁切轮廓。
- 8 条记录产生 8 个互不完全重叠的可见 bbox。
- 62 条记录不溢出、不产生横向页面滚动。

### 9.2 滚动与动画

- 罐体未进入视口时 `getAnimations()` 为 0，素材保持预备/最终安全状态。
- 模拟交叉比例达到阈值后出现预期动画，且 8 枚均具有不同的延迟或批次。
- 动画完成后每枚素材回到确定性最终 transform。
- 滚出再滚入不重放；切换月份后允许新月份播放一次。
- 保存新增记录只动画新增 ID；编辑和删除不重播全部 ID。
- reduced-motion 下始终无活动动画且最终内容可见。

### 9.3 趋势图真实可见性

- 有数据时 SVG `hidden === false`，bbox 宽高均大于 0。
- 轴线、文字、数据点均落在 viewBox 内。
- 至少一个 path 的 `getTotalLength() > 0`；稀疏记录存在明确的缺口桥接线。
- 可见点的 computed fill/stroke 不是 `none` 或全透明，线条与背景对比达到 3:1。
- 每个点的触摸命中区至少 44×44px。
- 390px 手机截图中图表位于图例和文字摘要之间，不能消失、重叠或被裁切。
- 空数据时不出现空白图框，显示明确空态。

### 9.4 回归矩阵

视口至少覆盖：

- 375×812；
- 390×844；
- 430×932；
- 844×390 横屏；
- 768×1024；
- 1440×900。

## 10. 人工验收脚本

1. 清理该路由的本次动画会话状态并打开当月心情页。
2. 停留在月历区域，确认下方未偷偷播放整罐动画。
3. 慢慢向下滑到心情罐，确认瓶体约三分之一出现后，8 枚表情依次从罐口落下。

5. 滑走再返回，确认整罐不重复播放。
6. 切换到上月，确认上月数据在进入视口时独立播放一次。
7. 回到本月新增一条心情，确认只有新增表情下落，页面不跳转且月历/统计/趋势同步更新。

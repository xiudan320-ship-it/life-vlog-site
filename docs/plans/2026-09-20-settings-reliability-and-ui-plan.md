## 3. S1–S3：缓存操作恢复

### 定位入口

`modules/routes/settings-route.js`、`modules/offline-settings-controller.js`、`modules/cache-management-view.js`、`modules/offline-cache-controller.js`、`modules/settings-event-bindings.js`、`modules/routes/controller-options.js`，以及必要的 runtime 装配局部。

### 最小实现

- 明确唯一的绑定所有者：推荐在现有 offline settings controller 增加实际可调用、幂等的初始化方法，由 settings route 在 DOM 挂载、collect 和 controller 创建之后调用。也可沿用设置事件层统一绑定，但不能两处都绑。
- 连接容量入口、窗口关闭/Escape、容量表单提交、预设按钮、缓存刷新、全部清理，并复用已有方法。把函数暴露在 return 里不等于完成接线。
- 关闭容量子窗口后回到“存储与数据”及原触发项；保存后摘要、真实容量和再次打开的值一致。不得用只改屏幕文本的方式模拟保存。
- 刷新显示真实计算状态，失败可重试；重复点击不并发启动多次计算。异步结束时只更新当前挂载且仍属于原账号的视图。
- 全部清理调用现有受管理缓存清理范围，保留账号、个人设置、未发布草稿与上传队列。先核查既有 `clear` 的实际范围再接线，禁止用 `localStorage.clear()`、清空全部 IndexedDB 或删除所有 origin 数据代替。
- “清除全部离线内容”应准确告知会清哪些本机内容，并用项目现有确认机制处理实际删除；取消不产生副作用。不要增加新通用确认框架，不把刷新/查看操作也改成需要确认。
- 保留已工作的分池下载/清理；同一按钮最多一个监听器。关闭重开设置、切换分区后不重复绑定。
- 不保留失效的可选初始化调用、无用解构参数或双重绑定路径。方法缺失应在开发测试中可发现，不能继续用 `?.()` 掩盖未完成装配。

### 验收

使用独立合成 key/cache 和容量：改日记/秘藏上限 → 保存 → 关窗 → 重开 → 刷新页面后值一致；预设和边界输入实际生效。注入确定大小的缓存后，刷新读数发生正确变化。全部清理只删除约定的缓存，合成登录、偏好、草稿、上传任务标记全部保留；分池清理只影响目标池。连续开关设置五次，单击只执行一次处理器。

## 4. S4/S5：设备能力与反馈必须真实

### S4a：安装应用

入口：`modules/app-runtime-startup.js`、`modules/pwa-install-controller.js`、settings route 与模板。

- 安装事件监听仍在启动阶段建立，不能为了晚绑定按钮而错过提前发生的 `beforeinstallprompt`。
- 视图节点在设置挂载后获取并绑定；事件缓存、UI 挂载和渲染分清责任。可沿用项目已有动态取 root/元素的方式，无需框架或轮询。
- 覆盖事件先到/后到、已经安装、用户取消安装、没有安装能力、需要系统操作说明等状态。不存在可用操作时显示真实原因或提示，不留下无内容的“安装应用”行。
- 只有用户点击才调用原生安装提示；取消或平台不支持不报安装成功。已消费的事件不能再次复用，重开设置不重复注册 window 事件。
- 测试中的合成事件只证明接线，实际原生安装结果必须另记；不能把 stub 的 dismissed/accepted 当成真机安装验收。

### S4b：通知检查与开启/关闭

入口：`modules/push-controller.js`、`tests/push-controller.mjs`、PWA 注册流程。

- 先检查已有测试与服务端契约，保留既有禁用顺序和账号隔离。对支持、未授权、拒绝、已订阅、未安装、注册失败分别呈现有意义状态。
- `navigator.serviceWorker.ready` 的无结果路径需要有退出加载态和重试的方式；已知注册失败或不具备能力时立即说明原因。必要的等待应有可解释的上限，不加入假进度、强制睡眠或无限轮询。
- 关闭设置、退出账号后旧检查不能重新打开页面或把新账号状态覆盖。操作中禁用重复提交，失败显示原因和恢复动作。
- 禁止为了通过检查而请求用户真实通知权限或发送真实测试推送。可在正式构建本机上下文使用可控 SW/Push fixture；实际真机推送未验证时如实记录。

### S5：诊断复制

入口：`modules/performance-diagnostics-view.js`。

确认 Clipboard API 存在并且 writeText 成功后才报成功；权限拒绝/不可用时展示“无法复制”及可理解的处理方式。复用现有反馈，不增加兼容复制库。失败不吞成成功，也不产生未处理 Promise rejection。保持内容脱敏，不能把凭据、私人记录加入复制结果。

验收包含：事件发生在设置之前与之后；多次重开；安装取消；剪贴板成功、拒绝、不存在；通知注册失败/未完成。每种状态都验证真实按钮行为和结果文案。

## 5. S6：返回、搜索与账号生命周期

- 入口：`modules/settings-shell-controller.js`、`modules/settings-shell-view.js`、`modules/settings-search-domain.js`、`modules/settings-section-registry.js`。
- 打开子窗口前记录原按钮与内容滚动位置；关闭或保存后恢复原分类、手机目录/详情层级和原按钮焦点。触发项已消失时选择可见的分类标题/合理邻近控件，不能聚焦隐藏节点。
- 保留 Escape/back 的层级：先关子窗口，再回手机目录，最后退出设置。关闭整个设置仍回到头像等原入口。
- 设置搜索结果必须符合当前权限和实际可用性。源码目前直接查询完整 registry，管理员 R2 等隐藏项可能仍出现在普通成员结果中；这是需角色 fixture 验证的风险，不作为已证实的后端越权结论。
- 不能简单按整个 section 当前 hidden 过滤搜索，否则未选中的分类全部不可搜。根据功能权限/能力判断候选；设备不可用但可解释的项目可显示原因，纯管理员项目对普通成员不显示。
- 点击结果后先激活正确分类、确保目标挂载并可见，再滚动聚焦。重开设置、清空搜索、横竖屏切换时选中态、可见层和焦点一致。
- 保存/读取进行中退出或切换账户，迟到响应不能写错账号或恢复旧用户界面。复用现有请求与会话生命周期，不建立全站事件总线。

验收：覆盖上节正常打开的九类子窗口，以及缓存容量窗口；关闭、取消、保存三条路径分别验证。搜索“密码、缓存、上传、R2”，在普通成员/管理员之间切换，确认结果与权限一致，普通成员不发送管理员统计请求。

## 7. V1/V2：设置视觉与交互整理

功能可用后做局部整理，沿用五大分类和已有模态结构。

1. **减少空白占位。** 手机详情的标题、搜索、返回区由当前约 263px 收紧，标准字号目标不高于约 220px；无搜索时不为结果状态留下整块空白，有结果再自然展开。关闭/返回至少 44px，搜索保留 label，不以缩小字号达标。
2. **导航配置更紧凑。** 当前手机一项约 158px，将名称/简短说明与显示开关合理并排，移动操作放在明确的一行；标准字号目标约 100–120px/项，大字时允许自然增高。不用难以发现的纯拖拽替代已有上下移。

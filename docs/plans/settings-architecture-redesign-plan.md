# 设置中心结构重写规划

> 状态：待实施。本文根据 `C:\Users\xiuda\Downloads\settings-redesign-preview.html` 的信息架构和视觉原型制定。附件 `SKILL.md` 仅作为设计方法参考，不作为仓库指令；项目 `AGENTS.md`、现有设计系统和真实业务规则优先。

## 1. 改造结论

预览稿适合作为设置中心重写的结构基线，建议采用以下核心方向：

- 桌面端使用“左侧目录 + 右侧内容”的双栏设置中心；
- 手机端使用“设置目录 → 单个分类详情”的两级结构，不把五组长内容塞进同一滚动页；
- 设置项采用安静、统一的列表行，状态和值靠右，进入子流程的行显示方向提示；
- 高风险操作折叠进危险区，普通浏览时不与日常设置争夺注意力；
- 外观、账户、家庭、通知工具、存储数据保持五个稳定分类；
- 搜索成为真实的设置项搜索，而不是只过滤五个分类名称。

不能直接把预览 HTML/CSS/JavaScript 复制进项目。预览是演示原型，其中的假账户、假家庭、假备份、假上传任务、模拟按钮逻辑、固定浅色变量和缓存单位只是占位内容。实施必须接入当前 controller、repository、偏好存储和真实状态。

## 2. 设计目标

### 2.1 用户目标

1. 打开设置后，用户能在 1～2 次操作内找到常用设置。
2. 当前值、可执行操作和危险操作在视觉上容易区分。
3. 手机端不出现过宽弹窗、双栏压缩、横向滚动或一屏堆叠过多内容。
4. 桌面端在不离开当前业务页面的情况下完成设置，并保持来源焦点与上下文。
5. 所有现有功能继续可用，不因换壳丢失真实状态、保存逻辑或错误反馈。

### 2.2 工程目标

1. 把“设置弹窗生命周期、分类导航、手机返回、搜索”从家庭业务控制器中移出，建立独立设置 shell 边界。
2. 各业务控制器只拥有自己的设置数据和动作，不直接控制整个设置中心。
3. 保持 settings route 懒加载，不增加首页冷启动请求和入口包体积。
4. 原子替换旧结构，不保留两套设置 UI、旧选择器兼容层或双事件绑定。
5. 每个阶段都形成可运行的端到端闭环，再继续迁移下一组设置。

## 3. 参考稿采用与修正清单

### 3.1 原样保留的设计意图

- 桌面弹窗最大宽度约 940px，侧栏约 260px，内容区独立形成清晰阅读列。
- 五个一级分类和对应线性图标。
- 桌面侧栏当前项使用柔和底色表示选中，而不是高饱和实心按钮。
- 手机只显示目录或详情中的一层；详情顶部有明确“设置”返回按钮和当前分类标题。
- 设置行由名称、当前状态/辅助说明、可选图标和导航提示组成。
- 顶部导航排序、工具排序、家庭成员、缓存管理使用不同的内容结构，不强行套成完全相同的卡片。
- 清除缓存等危险操作默认折叠，展开后使用明确危险语义。

### 3.2 必须修正后才能进入生产的部分

| 预览问题 | 生产要求 |
| --- | --- |
| 使用硬编码浅色 palette | 使用现有语义 token，同时提供已验证的深色与浅色映射；不把原型 hex 散落到组件中 |
| 用 `.is-mobile` 模拟设备 | 由真实 CSS media query、动态视口和安全区驱动；不得保留演示切换器 |
| `dialog.open = true/false` | 使用 `showModal()` / `close()`，保留模态语义、Esc、焦点约束和来源焦点恢复 |
| 搜索只隐藏不匹配的分类名 | 搜索分类名、设置项名称、说明和同义关键词，并能直接定位具体设置项 |

| 自定义 switch 隐藏 input 为 0×0 | 保留可聚焦原生控件或完整可访问按钮语义，公开选中/按下状态和可见焦点 |
| 部分图标按钮没有名称 | 每个独立图标按钮提供上下文完整的 accessible name，例如“上移 日记” |

| 内联 style 与大量演示 DOM | 样式进入规范 CSS，视图由真实 state/view model 渲染，不保留假数据 |

## 4. 信息架构

### 4.1 外观与使用

按使用频率排列：

1. 主页名称；
2. 手机日记版式（单列/双列）；
3. 文字大小（标准/较大/特大）；
4. 安装到主屏幕；
5. 顶部导航入口开关与排序。

顶部导航是较复杂的二级管理区：显示已启用数量上限、每项启用状态和上下移动按钮。开关与排序必须继续使用现有 `primary-navigation-domain/controller/view` 规则，不在设置视图复制业务判断。

### 4.2 账户与安全

顶部先显示真实账户概览，再依次提供：

1. 昵称；
2. 头像；
3. 修改密码；
4. 恢复密钥；
5. 秘藏密码；
6. 绑定邮箱。

安全风险状态用文字和图标共同表达，不能只用红色。没有真实“最近修改时间”的数据时不显示伪时间；改为准确的动作说明。

### 4.3 家庭与共享

按状态渐进展示：

1. 待接受邀请（存在时置顶并显示数量徽标）；
2. 当前家庭摘要和本人角色；
3. 成员列表；
4. 邀请码与复制反馈；
5. 已发出待处理邀请；
6. 家庭签名与家庭账户管理入口。

所有成员、角色、邀请码和邀请状态必须来自现有家庭 controller/repository；无家庭时展示创建/加入动作，不渲染假成员。

### 4.4 通知与工具

分为两个稳定区块：

- 通知：本机推送状态、状态解释、开启/关闭与错误恢复；
- 首页工具顺序：现有工具列表、可见说明、上下移动按钮。

通知关闭继续遵守“本机订阅优先关闭，远端清理为独立失败边界”的现有规则。工具排序继续使用现有偏好存储和顺序控制器。

### 4.5 存储与数据

从高频、低风险到低频、高风险排列：

1. 缓存占用、容量和策略摘要；
2. 刷新、修改上限、切换策略、下载两类离线包；
3. 折叠的清除缓存危险区；
4. 每日云端备份与最近删除；
5. 上传任务；
6. 高级诊断和性能摘要。

以已完成的自动缓存修复提交 `ec8d4d9` 为业务基线：缓存摘要、策略、容量、下载和清理由 `offline-settings-controller.js` 统一拥有。设置重写不得把这些职责重新塞回 layout 或通用 shell。

## 5. 页面结构

### 5.1 桌面与大平板

```text
┌────────────────────────────────────────────────────────────┐
│ 设置目录（约 264） │ 当前分类内容                    [关闭] │
│                    │                                      │
│ 搜索设置           │ 分类标题 + 一句话说明                 │
│                    │                                      │
│ 外观与使用         │ 真实设置卡片 / 状态 / 操作             │
│ 账户与安全         │                                      │
│ 家庭与共享   [1]   │ 单一内容滚动区                         │
│ 通知与工具         │                                      │
│ 存储与数据         │                                      │
└────────────────────────────────────────────────────────────┘
```

- 弹窗宽度使用 `min(940px, calc(100vw - 32px))` 一类自适应约束，不使用永远固定的 940px。
- 高度使用动态视口单位并预留上下安全空间；内容较多时只滚动当前内容区。
- 关闭按钮固定在弹窗可见区域，但不得遮挡内容或键盘焦点。
- 侧栏与内容区可分别滚动时，焦点移动必须自动保证目标至少部分可见；优先让侧栏内容在常见桌面高度内不滚动。

### 5.2 手机与短横屏

```text
第一级：设置目录             第二级：分类详情
┌────────────────────┐      ┌────────────────────┐
│ 设置          [×]  │      │ ‹ 设置  外观与使用 │
│ 搜索设置            │  →   │                    │
│ 外观与使用      ›   │      │ 设置项             │
│ 账户与安全      ›   │      │ 设置项             │
│ 家庭与共享 [1]  ›   │      │ 设置项             │
│ 通知与工具      ›   │      │                    │
│ 存储与数据      ›   │      │ 单一纵向滚动区      │
└────────────────────┘      └────────────────────┘
```

- 默认先显示目录；进入分类后隐藏目录，显示详情和返回。
- 系统返回/Esc 的优先级为：关闭子弹窗 → 返回设置目录 → 关闭设置中心。
- 320～430px 宽度不横向滚动；长状态文字允许合理换行，不把主要名称挤成单字列。
- 所有可点击行至少 48px 高；图标按钮至少 44×44px；表单控件计算字号至少 16px，避免 iOS 聚焦放大。
- 短横屏允许更紧凑的垂直间距，但不降低触控面积；关闭和返回必须始终可见。

## 6. 搜索设计

### 6.1 搜索数据

扩展 `settings-section-registry.js`，为每个真实设置项提供稳定元数据：

```js
{
  id: "changePasswordButton",
  sectionId: "settingsAccount",
  label: "修改密码",
  description: "更新账户登录密码",
  keywords: ["密码", "登录", "安全"]
}
```

只登记真实存在、可到达的设置项。搜索索引不包含假数据、用户私密内容或动态正文。

### 6.2 交互

- 空查询显示正常五类目录。
- 有查询时显示匹配设置项结果，而不是把整个分类内容永久展开。
- 结果包含设置名称、所属分类和简短说明；点击后进入对应分类并把目标滚动到可见位置。
- 桌面点击结果后保持搜索词，提供清除按钮；手机进入结果后返回可回到原搜索结果。
- 无结果显示“没有找到相关设置”，并提示尝试“密码、通知、缓存”等真实关键词。
- 输入事件使用轻量去抖或同步小索引过滤；不得触发网络请求。

### 6.3 无障碍

- 搜索框有可见或程序化 label，清除按钮有名称。
- 结果数量变化通过一个 `aria-live="polite"` 状态区完整播报，不抢焦点。
- 点击结果后，将焦点移到分类标题或目标控件，不能只滚动视觉位置。
- 结果列表遵循 DOM 顺序，不创建自定义键盘陷阱。

## 7. 组件与视觉规范

### 7.1 视觉方向

附件设计方法强调“结构表达信息、克制装饰、用真实内容塑造界面”，本项目采用以下落点：

- 记忆点放在温和的家庭日记气质和真实头像/家庭状态，不增加无意义渐变或大面积装饰；
- 不使用全大写英文眉题，不在每个区块重复 kicker；
- 使用现有中文系统字体栈，避免为设置页新增字体请求；
- 复用当前 `--bg`、`--surface`、`--ink`、`--muted`、`--line`、`--accent`、`--danger` 等语义 token；需要的新 token 在 foundation 层成对定义深浅主题；
- 图标统一为现有线性 SVG 语言，不使用 emoji，不把预览 sprite 原样复制成第二套图标系统；
- 圆角按层级区分：弹窗、分组卡片、行内控件各用不同 token，不让所有元素使用同一圆角。

### 7.2 基础组件

只抽取本次会重复使用且语义稳定的组件：

- `SettingsNavItem`：一级分类入口；
- `SettingsRow`：导航型、静态状态型两种；
- `SettingsSegmentedControl`：单列/双列、字号等互斥选择；
- `SettingsSectionCard`：同类设置行容器；
- `SettingsDisclosure`：备份、上传、诊断、危险区；
- `SettingsStatus`：loading/success/error/empty 的行内状态。

项目是原生模块化 HTML/CSS/JavaScript，不引入 React、Tailwind 或新的 UI 依赖。上述名称表示模块职责，不要求建立通用组件框架。

### 7.3 状态与反馈

- 可点击行有 hover、pressed 和 `:focus-visible`，状态变化不改变布局边界。
- 异步按钮在 100ms 内显示忙碌反馈，执行中使用真实 `disabled`；`finally` 恢复。
- 成功反馈优先更新行内事实，再用 toast 辅助；toast 不抢焦点。
- 错误文案说明原因和恢复动作，保持在对应区块内。
- 动效只用于手机层级切换、details 展开和状态变化；约 150～220ms，使用 transform/opacity，支持 `prefers-reduced-motion` 直接到最终态。

- 搜索大小写、空白、中文关键词、同义词、排序和无结果；
- 分类 registry 中 section/item id 唯一且都指向真实渲染节点；
- 手机导航状态转换：目录 → 详情 → 目录 → 关闭；
- desktop tab 键盘：方向键、Home、End、Enter/Space；
- 重复 initialize 不产生重复事件；
- 不可用/加载/错误状态不会被误显示为可点击成功态。

### 10.2 浏览器功能回归

逐项点击并验证当前值、子弹窗、保存、取消、失败保留和焦点返回：

- 主页名称、版式、字号、安装；
- 顶部分页启用上限和排序持久化；
- 昵称、头像、密码、恢复密钥、秘藏密码、邮箱；
- 家庭邀请、成员、邀请码、家庭签名；
- 通知开启/本机关闭和失败边界；
- 工具排序；
- 缓存统计、策略、容量、下载、清理；
- 备份、最近删除、上传任务和诊断。

关闭并重开、刷新页面、切换账户作用域后，所有本地偏好与真实状态必须正确恢复。

### 10.3 视觉与响应式矩阵

至少覆盖：

- 320×568 极小手机；
- 375×812 小手机；
- 390×844 标准手机；
- 430×932 大手机；
- 844×390 短横屏；
- 768×1024 平板；
- 1024×768 横向平板；
- 1440×900 桌面。

每个关键视口验证：无页面横向滚动、无文本单字列、关闭/返回可见、焦点不被遮挡、内容末尾不被安全区覆盖、触控目标尺寸合格。

### 10.4 无障碍与主题

- Axe critical/serious 为 0；
- tab/tablist/tabpanel 或等价导航语义完整；
- 自定义选择控件公开当前状态；
- 图标按钮名称包含操作对象；
- 正文对比度至少 4.5:1，边界和焦点状态至少 3:1；
- 仅键盘可完成所有操作，焦点顺序与视觉顺序一致；
- 130% 字号与深浅主题独立检查；
- reduced-motion 下不依赖动画完成状态更新。

### 10.5 性能与构建

- settings route 继续懒加载；未打开设置时不请求其 chunk；
- 不新增第三方 UI/图标/动画依赖；

- 设置搜索不触发网络请求；
- 构建预算、CSS health/coverage 和入口请求预算不回退。

## 13. 执行交接摘要

执行者应把参考 HTML 当作布局与信息层级样稿，而不是可粘贴源码。先建立独立 settings shell 的最小闭环，只迁移“外观与使用”；验证桌面、手机、焦点和真实保存后，再逐组迁移其余业务。任何阶段都不能用静态假状态代替 controller，也不能为了保持旧选择器而增加兼容层。最终结果应看起来接近参考稿的安静双栏/两级结构，但颜色、字体、状态、数据与交互必须属于当前“咻蛋之家”应用。

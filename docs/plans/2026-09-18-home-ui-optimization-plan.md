## 1. 目标与范围

在保留绿色系明暗主题、黑猫封面与 Logo、现有导航和桌面四列日记流的前提下，完成四项优化：

| 编号 | 问题 | 目标结果 |
| --- | --- | --- |
| A | 管理员存储统计挤占桌面导航 | 统计迁入设置的“存储与数据”，顶部导航和常用操作不重叠 |

| C | 桌面日记卡片管理按钮过多 | 卡片保留收藏，其余有权限的管理操作集中到“更多” |

本轮不改后端接口、数据库结构、权限政策、日记数据模型、登录流程、缓存策略或发布设施；不引入 React/Tailwind 等新框架，不改写受保护图片，不重做日记详情、心情页或整个设置中心。

## 3. 执行顺序与阶段交付

1. 复用 [Figma 工作流](../FIGMA_WORKFLOW.md) 第 9 节已有文件；尚未关联时，按当前技能创建项目 Design 文件。记录真实 fileKey、节点链接和基准提交。
2. 复用 `tests/fixtures/cloudflare-api-fixture.mjs` 和现有浏览器测试的会话注入方式，在本地运行当前源码。不得使用真实账号、密码、token、日记或照片。
3. 准备管理员和普通成员两种首页状态；管理员场景必须能显示现有存储统计，避免漏掉顶部拥挤问题。准备有记录、未记录的心情，及四到六周的月份。
4. 首轮基准截图只拍 1440×1000、390×844 的稳定浅色状态，并核对深色样式；等待实际数据和字体就绪，不用固定长时间 sleep。记录顶部、概览、搜索和首卡位置，以及初始滚动位置。
5. 若健康场景因 fixture 缺少 schema/配置响应而出现技术告警，仅补齐对应合成响应；错误态单独保留。不得通过删除生产告警或修改线上数据库来美化截图。

完成条件：有可复现的基线、可访问的 Figma 文件、四项问题的实际定位。遇到权限或工具限制时继续完成不依赖它的源码定位和验证准备，并准确记录阻塞；不能声称已完成 Figma 交付。

按 [Figma 工作流](../FIGMA_WORKFLOW.md) 选择当次安装的相关技能：创建文件时读 `figma-create-new-file`，制作页面时读 `figma-generate-design` 与 `figma-use`，实现节点前读 `figma-design-to-code`。不要假设此前修改过的旧插件缓存仍是当前有效版本。

- 制作手机 390px、桌面 1440px 的浅色/深色首页，共四个主要视图；以可编辑布局、文字和控件交付，不把整页截图充当设计稿。
- 附上存储设置区域和卡片“更多”展开状态的小范围视图，不另做完整设置中心或组件库。

## 4. 四项实施要求

### A. 存储统计迁入设置

**设计决策：**从顶部彻底移除 R2 用量入口，放入设置 → 存储与数据。保留已用容量、本月上传量和管理员访问 Cloudflare 控制台的能力；与“本机缓存占用”分组标注，避免混淆远端存储和本机缓存。

实施要点：

- `modules/admin-storage.js` 当前在模块顶层查询 `#adminStorageMeter` 等 DOM。设置页是懒加载，不能只移动 HTML；调整为设置 DOM 挂载后初始化，或按调用时的有效 root 渲染。
- 在管理员实际进入相关设置区域时读取数据，保留加载、失败和重试状态。清理首页账户同步时的旧请求触发与失效装配依赖；不新建定时轮询服务。
- 设置多次进入不重复绑定事件，不并发发起相同请求。账号切换/退出后清理旧结果，迟到的成功或失败响应不得写入新账号界面。
- 普通成员和未登录状态不展示该管理区域，也不发起管理 API 请求；沿用服务器端既有权限边界。
- 按既有设置搜索机制接入入口。若为搜索增加 registry 条目，同时保证普通成员搜不到不可用管理操作。
- 保留主题、通知、等级及账户入口的正常布局；不通过缩小点击区域来腾出空间。

验收：管理员首次打开设置即能看到加载与结果；失败能重试；管理员切换普通成员后旧数据显示被清除；首页不再请求存储统计；各目标宽度顶部控件与导航边界不相交。

### B. 压缩今日概览与月历

**设计决策：**普通桌面保持今日心情与本月日历两个区块，取消为填满月历高度而放大的成员卡片；月历使用紧凑缩略网格，完整交互仍通过“查看心情日历”进入原页面。

- 普通桌面缩紧概览内边距、标题间距和月历单元，两个成员条目使用自然高度。避免继续使用无必要的 `height: 100%` / `flex: 1` 将少量内容撑高。
- 缩略月历保留月份、今天标记和记录概况，四、五、六周都能完整显示。若日期单元仅用于展示，不为本轮新增日期点击行为；现有日历入口保持易触控。
- 手机继续展示两位成员的今日状态和日历入口，不新增整月网格；本人添加/查看心情沿用共享 overlay，保留 loading、empty、error 和重试。
- 1900px 以上保留右侧上下排列的心情侧栏及与中央内容的间距；其高度仍不能撑开中央内容行。必须检查 2048px 与 3750px，不能只修 1440px。
- 保留黑猫横幅及既有首次登录定位、深链和返回滚动恢复行为。不能通过改变初始滚动位置、隐藏横幅或把必要内容设为不可见来达到“更早看到日记”的指标。
- 本项允许修订 MASTER 中“普通桌面两块强制等高/成员填满面板”的旧细则，以紧凑自然高度替代；同步最终规范，保留双主题、四列日记和超宽侧栏约束。

验收：健康 fixture、默认字号、相同初次登录落点下，1440×1000 首张日记卡至少露出 120px 媒体区域；390×844 结合 D 项至少露出 180px。同时记录前后 `#overview` 高度和首卡 top，不依赖单张截图判断。大字模式允许自然增高，以完整可读和不遮挡为准，不强套上述高度指标。

### C. 整理桌面日记卡片操作

**设计决策：**桌面列表卡片常驻“收藏”和有内容时的“更多”；管理操作进入“更多”。置顶、精选状态仍在原状态标记中显示，评论预览保持原行为。

权限须与当前实现一致：

| 当前身份与记录关系 | 常驻操作 | 更多中的操作 |
| --- | --- | --- |
| 未登录 | 沿用当前浏览能力 | 无管理菜单 |
| 普通成员查看他人记录 | 收藏 | 无可用操作则不显示“更多” |
| 本人记录 | 收藏、更多 | 编辑、精选/取消精选、置顶/取消置顶、删除 |
| 管理员查看他人记录 | 收藏、更多 | 修改分类、删除；已置顶时保留管理员取消置顶 |

- 管理员查看本人记录时去重相同功能，不能出现两个“取消置顶”。缺失 owner 等特殊记录继续依照当前权限契约处理，不借此次 UI 修改改变授权规则。
- 现有 `getDiaryActionModel` 主要服务手机详情，并不含桌面的全部精选/置顶操作。不能直接替换桌面判断导致功能丢失；优先复用已适用的逻辑，只在确有共同职责时抽取小范围纯函数。
- 复用项目适用的菜单/披露交互；若需独立控制器，仅处理本菜单生命周期，不建设通用弹层框架。菜单不依赖 hover，键盘能打开、操作和关闭，Escape/外部点击关闭并合理恢复焦点。
- 保留现有删除确认、busy 状态及请求处理器；点击菜单操作不能冒泡打开日记详情。异步操作和列表重绘后，菜单与焦点不能指向另一篇日记。
- 当前 `bindGalleryActions` 通过容器委托和 `data-*-index` 处理按钮。调整 DOM 后确保事件仍能到达原处理器；若菜单脱离该容器，必须显式正确转发，不能留下无响应按钮。
- 菜单不能被瀑布流卡片、媒体容器或滚动区域裁剪；每次最多打开一个卡片菜单。使用稳定 photo ID 管理当前目标，列表排序/筛选/重绘时清理过期状态。
- 手机列表和手机详情保留已有操作路径；本轮不把桌面管理按钮重新铺到手机卡片上。

验收：上述身份矩阵、菜单开关/焦点、每个实际动作、取消删除、操作失败，以及筛选/重排后的记录目标正确。相关浏览器/发布冒烟测试若此前直接点击外露按钮，应改为通过用户实际菜单路径操作，不修改测试为强行点击隐藏元素。

### D. 手机工具标题与搜索区域

**设计决策：**保留默认首屏三个完整工具卡片及既有横向滑动/排序机制；允许工具名称合理换行。搜索保留原能力，改为紧凑的一行输入区域。

- 首屏“时间纪念册”“本周回顾”“留言”显示完整；优先调整图标与文字排布，必要时两行显示，不使用省略号或把文字缩到难读来凑宽度。
- 不把默认工具名称改短、不改变默认顺序，不将后续工具从横向列表删除。第一屏仍完整呈现三个卡片，不露出半张第四卡。
- 触控区域至少 44×44 CSS px，相邻操作保留当前设计要求的间距；大字模式可增加卡片高度，避免切字和工具间重叠。
- 搜索的视觉标签可与输入整合，必须保留可访问名称。默认字号下搜索容器建议不超过 64px，输入本身至少 44px 高、计算字号至少 16px。
- 保留搜索建议、清空、日期/标题/正文/分类匹配；分类条在自己的容器内横向滚动，搜索与筛选仍在普通文档流中，不新增 sticky/fixed 占位。

验收：375、390、430px 默认三个名称完整；实际点击和滑动正常；大字模式无截断；搜索输入、建议、清空和分类筛选与现有功能一致。

## 5. 验证方案

不操作真实账户或生产数据，不为视觉优化运行远程 DDL。只对新增行为和真实回归风险补测试，避免逐条镜像 CSS 实现。

### 自动化与行为验证

- A：补充/扩展存储控制器的确定性请求测试，覆盖懒加载后挂载、非管理员不请求、重复打开不重复绑定、退出/切号后的迟到响应。补设置入口与搜索权限的浏览器路径。
- B：用已就绪的相同 fixture 比较概览高度和首卡位置；保留首页冷启动、显式深链、返回滚动恢复及超宽侧栏不撑高主流的回归。
- C：权限组合可用纯函数测试；浏览器验证真实菜单与处理器链路、确认取消、错误恢复和列表重绘。不要只用 markup 正则证明交互正常。
- D：验证工具文字实际溢出、前三卡完整可见、点击区域以及搜索/分类行为；保留手机单列/双列用户设置。

现有定位入口：`tests/diary-gallery-view.mjs`、`tests/diary-action-domain.mjs`、`tests/today-mood-controller.mjs`、`tests/settings-section-registry.mjs`、`tests/primary-navigation-domain.mjs`、`tests/browser-regression.mjs`、`tests/release-smoke.mjs`。只在影响对应契约时修改断言；应替换已获本规划调整的等高/外露按钮旧断言，保留权限、无溢出和启动行为约束。

### 最终检查范围

本轮涉及共享顶部与响应式布局，因此执行一次完整宽度矩阵：375、390、430、768、1024、1440px，侧栏另查 2048、3750px。手机补横屏与已有大字模式；浅色/深色均检查，核心交互在代表宽度验证，不把所有状态与所有宽度机械做笛卡尔积。

1. 运行直接受影响的单元/模块测试及 `pnpm run check`、`pnpm run test:static`、`pnpm run test:structure`。
2. 对最终代码运行 `pnpm run build`、`pnpm run test:build`，再运行使用该构建的相关浏览器回归；避免读取遗留 dist 验证旧页面。
3. 按现有脚本前提准备本地服务，使用 fixture 运行必要的 Axe 检查，人工验证键盘、触摸、焦点恢复、菜单遮挡和减少动态效果。若新增 browser 断言，接入已有测试入口。
4. 只有新改动、失败或未决风险才扩大/重跑验证。获准正式发布时再按发布清单执行其完整门禁，不在本文复制一套发布流程。

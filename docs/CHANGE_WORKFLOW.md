# 技术文档与变更记录流程

这套流程用于保证新对话、其他开发程序和未来维护者不需要依赖聊天历史，也能判断项目当前状态。

## 1. 强制规则

每个修改仓库内容的任务都必须完成以下动作：

1. 开始前阅读 `AGENTS.md` 和 `docs/README.md`。其他文档按照 `docs/README.md` 的任务路由按需查阅，不得默认批量读取。
2. 开始前运行 `git status --short`，保留不属于当前任务的改动。
3. 使用文件名、关键词或 `rg` 定位相关源码和文档章节，再读取必要上下文。
4. 只有涉及架构、数据流、缓存、PWA、构建、部署或关键系统契约时，才读取 `docs/TECHNICAL_OVERVIEW.md` 的相关章节。
5. 只有涉及模块位置、模块边界、模块新增/删除/移动或职责变化时，才读取 `docs/MODULE_MAP.md` 的相关章节。
6. `plans/` 中的 `*-plan.md`、`history/` 中的审计/恢复记录，以及调查、迁移和历史验收文档不属于默认上下文，仅在当前任务与该专项直接相关时查阅。
7. 修改代码、样式、配置、schema、依赖、测试或部署逻辑时，同步更新根目录 `CHANGELOG.md` 的 `[Unreleased]`。
8. 如果模块职责、数据流、构建、部署、数据库或 UI 规范变化，同时更新对应长期文档。
9. 运行与风险相称的测试，并在交付说明中报告实际结果。
10. 提交前运行 `git diff --check`，确认应同步的变更日志和技术文档已包含在修改中。

纯文档拼写修正也要在 `[Unreleased] → Documentation` 记录，可以将同一任务内的多处文档修正合并为一条。

## 2. 应该更新哪份文档

| 变化 | 必须更新 |
| --- | --- |
| 任意仓库修改 | `CHANGELOG.md` |
| 新增、删除、移动模块或职责变化 | `docs/MODULE_MAP.md` |
| 架构、数据流、缓存、PWA、构建或关键依赖变化 | `docs/TECHNICAL_OVERVIEW.md` |
| D1 表、字段、索引或 Worker API 变化 | `schema.d1.sql`、后端说明、技术总览、变更日志 |
| 发布脚本或测试门禁变化 | `docs/release-checklist.md`、技术总览、变更日志 |
| UI 设计系统或全局交互规则变化 | `design-system/life-vlog/MASTER.md` 或页面 override、变更日志 |
| 单轮复杂任务的审计与验收 | 新增或更新专项规划书，并在长期文档记录最终事实 |

## 3. CHANGELOG 写法

### 默认读取范围

处理当前开发任务时，默认只读取 `CHANGELOG.md` 的 `[Unreleased]` 部分。

不要为了开始普通任务读取完整历史 CHANGELOG。

只有以下情况才向历史版本继续搜索：

- 调查回归问题；
- 查找某项行为何时引入；
- 追踪历史架构或数据迁移；
- 用户明确要求检查历史版本；
- `[Unreleased]` 无法解释当前行为。

需要查询历史记录时，优先使用关键词搜索定位具体版本或条目，再读取局部内容。

使用以下分类：

- `Added`：新增功能、模块、页面或能力。
- `Changed`：已有行为、架构、UI、配置或依赖变化。
- `Fixed`：用户可见故障或明确缺陷修复。
- `Removed`：删除功能、旧实现、兼容层或过时文件。
- `Security`：权限、认证、敏感数据和安全边界。
- `Documentation`：文档体系或说明变化。

每条记录必须说明“发生了什么”和“影响哪里”，不要只写文件名，也不要复制聊天过程。例如：

```markdown
- 日记列表改为只播放最接近视口中心的一个静音视频预览，8 秒以上视频不再循环。
```

未部署的内容写在 `[Unreleased]`。正式部署后，将对应条目移动到带日期的版本小节，并记录部署范围或关键提交。

## 4. 提交建议

一次提交只包含一个完整目的。推荐前缀：

- `feat:` 新功能
- `fix:` 缺陷修复
- `refactor:` 不改变用户行为的结构调整
- `docs:` 纯文档
- `test:` 测试体系
- `build:` 构建或发布

代码提交中应同时包含对应的 `CHANGELOG.md` 和长期文档修改，禁止先提交代码、长期不补文档。

## 5. 交付检查

- [ ] `CHANGELOG.md` 已记录本次所有修改。
- [ ] 模块职责变化已同步 `MODULE_MAP.md`。
- [ ] 架构或运维事实变化已同步 `TECHNICAL_OVERVIEW.md`。
- [ ] UI 规则变化已同步 design system。
- [ ] 测试和发布命令与文档一致。
- [ ] 文档没有密钥、token、真实密码或私人业务内容。
- [ ] `git diff --check` 通过。

> 状态：实现完成，待主任务审计；本轮未部署。本文件同时保留问题根因、验收契约和实现证据，不能替代线上发布记录。
>
> 编写日期：2026-09-01
>
> 现场证据：用户提供的两张 iPhone 深色模式截图；当前回复链在深层级后被挤到屏幕最右侧，正文只剩单字换行，留言表单前出现大面积无效空白。
>
> 前置实现：Luna 分支提交 `f45c0b5` 已完成 V2 瓶体、重播和大趋势图。本规划在该提交上继续，覆盖 V2 中“预设槽位 + WAAPI 轨迹”的下落方案，但保留已完成的瓶体视觉、趋势图和无障碍基础。

## 1. 本轮目标

本轮同时解决两个互不混写、但都需要移动端视觉验收的问题：

1. 留言或回复很多、回复层级很深时，评论内容仍占据稳定的可读宽度，不向右漂移、不出现一字一行、不产生横向滚动，留言表单始终在评论列表之后正常占满内容区。
2. 心情表情从瓶口缓慢、自然地落下，真实受到重力、瓶壁、瓶底和其他表情的碰撞约束；落地后有轻微滚动、弹跳和挤压调整，最终形成每次可复现的自然堆叠。
3. 点击瓶子重新播放时，从空瓶状态重新运行同一套物理过程；播放中再次点击立即取消旧模拟并从头开始，不叠加循环。
4. 不破坏 V2 已完成的瓶子高保真外观、大趋势图、稀疏日期布局、切月刷新、键盘操作和 reduced-motion。

## 2. 已确认根因

### 2.1 留言线程宽度失控

当前实现有两层叠加缩进：

- `mobile-diary-view.js` 递归输出 `.photo-comment-thread`，子回复真实嵌套在父回复容器内部；
- 每个节点又写入 `--comment-depth`，全局样式使用 `margin-left: calc(var(--comment-depth) * 28px)`；
- 嵌套节点还额外获得左边框和 `padding-left: 10px`；
- 手机覆盖样式仅把单次缩进改为 12px，并没有取消祖先容器的累计宽度。

因此第 3、4 级回复承受的是所有祖先宽度、各级 margin 和 padding 的总和，而不是“最多缩进一次”。截图中评论主体从约 x=267px 开始，深层正文被压缩到只有一个汉字宽，证明问题是结构性累计，不是文字本身或字体大小造成的。

### 2.2 心情瓶没有物理碰撞

当前 V2 的 `buildMoodJarItems` 先按行列计算固定 `x/y` 槽位，播放时 `animateJarNode` 只把每枚表情沿预设关键帧移动到该槽位：

- 表情之间互不知道彼此的位置和半径；
- 没有圆形刚体相交检测与分离；
- 没有瓶壁法线、瓶底约束、摩擦、恢复系数或休眠；
- 视觉上的回弹只是每枚元素独立的 easing，与实际接触无关。

所以目前是“落到预排好的位置”，不是“落入瓶子并碰撞堆积”。V3 必须替换这条运动路径，不能只继续调整 CSS duration 或 cubic-bezier。

## 3. 留言线程重构

### 3.1 数据结构：保留关系，取消递归布局

新增纯函数模块 `modules/comment-thread-domain.js`，负责把原始评论树转换为扁平行模型：

```js
{
  id,
  parentId,
  rootId,
  logicalDepth,
  authorId,
  replyTargetId,
  replyTargetName,
  body,
  createdAt
}
```

规则：

- `logicalDepth` 只用于语义、排序和测试，不直接换算为 CSS margin；
- 所有评论最终作为 `.photo-comment` 的同级 DOM 节点输出，禁止把回复节点继续嵌套进父节点；
- 顺序保持“根评论 → 该会话的回复”，同一会话内按现有创建时间和稳定 id 排序；
- 回复目标通过现有“回复 某人”文字表达，深层回复仍能看出在回复谁；
- 父评论缺失或已删除时，回复仍显示为普通行，目标显示安全的回退文案，不丢失内容；
- 遇到循环 parent_id、孤儿节点或重复 id 时必须终止遍历并稳定输出，不能无限递归。

移动日记页和桌面照片详情都复用该纯领域模型，避免两个入口继续维护不同的树算法。视图渲染可以保留各自模块，但不得重复实现树遍历规则。

### 3.2 手机端视觉规则

在 `max-width: 700px`：

- 所有评论行占评论容器完整可用宽度，`margin-inline: 0`；
- 回复不再按层级横移；最多使用一个固定的视觉提示，例如 2px 左边线或浅色回复底纹，但它不能改变正文可用宽度；
- 评论行使用 `grid-template-columns: 40px minmax(0, 1fr)`，操作区放在正文列内部，禁止第三列把正文再次挤窄；
- `.photo-comment-main`、header、作者行、正文和操作区全部设置 `min-width: 0`；
- 正文 `font-size >= 16px`、`line-height: 1.55～1.7`，中文按正常字词换行；连续 URL 使用 `overflow-wrap: anywhere`；
- 头像固定 36～40px，作者、作者徽章和回复对象允许换行但不得覆盖正文；
- “回复”“删除”触控区域至少 44×44px，视觉文字可以较小，命中区域用 padding 扩充；
- 任何评论深度下，正文列在 375px 视口至少保留 260px，在 320px 视口至少保留 205px；
- `.mobile-diary-page`、评论区、列表和表单必须满足 `scrollWidth <= clientWidth + 1px`。

桌面端可用一个固定的一级回复提示，但同样禁止随深度累计。建议根评论无缩进，所有回复统一 `margin-left: 20px`，不区分第 2～第 N 层。

### 3.3 表单与长列表

- 留言表单仍处于列表之后的正常文档流，不使用会被评论高度或嵌套宽度影响的 absolute/fixed 定位；
- 表单宽度为评论容器的 100%，textarea 和发送按钮 `box-sizing: border-box`；
- 回复状态条只显示当前目标，不给表单增加横向缩进；
- 软键盘弹出后，输入框可通过 `scrollIntoView({ block: "nearest" })` 保持可见，但不得造成页面横移；
- 本轮不新增“折叠更多”或分页交互。先正确显示全部现有评论；只有真实性能数据证明需要时才另立任务。

## 4. 心情瓶物理模型

### 4.1 模块边界

新增 `modules/mood-jar-physics.js`，只处理确定性模拟，不访问 DOM：

- 输入：瓶内边界、表情列表、形状/视觉半径、种子、出生时间、模拟配置；
- 输出：每枚表情按时间排列的 `x/y/rotation/state` 轨迹与最终稳定位置；
- 不读取真实账户，不发网络请求，不修改日记数据；
- `mood-month-summary-view.js` 只负责启动/取消播放并把轨迹转换为 `transform`；
- `mood-month-summary-domain.js` 继续负责月份汇总和情绪元数据，不承担逐帧 DOM 副作用。

不引入完整游戏引擎。当前最多 62 枚近似圆形图标，使用小型固定步长二维粒子求解器即可形成可维护的最小闭环；若实现后无法满足帧预算，必须先提供测量证据，再讨论新增依赖。

### 4.2 统一瓶体边界

物理边界必须与用户提供的 360×480 透明圆肚玻璃罐资源共用同一组几何常量，不能另画一只“看不见的方盒子”。

建议在纯模块中提供：

- `getJarInnerBounds(y)`：根据高度返回当前瓶内左/右边界；瓶颈窄、肩部逐渐张开、罐腹最宽；
- `getJarFloorY(x)`：根据横向位置返回椭圆瓶底内缘高度；两侧高、中间低；
- `getJarMouthSpawn(seed)`：只在瓶口内缘安全宽度生成出生点；
- 所有边界比可见玻璃内缘向内缩 4～8 个 viewBox 单位，保证图标整圆不压线或穿墙。

边界与 SVG 锚点共享导出常量或同一个领域函数，修改瓶体比例时物理轮廓同步变化。

### 4.3 刚体近似与碰撞

每枚心情图标按圆形刚体处理；方形成员只改变视觉裁切，不改变碰撞代理，避免角点卡进瓶壁。

固定时间步：

- `dt = 1 / 60s`；慢帧时累计时间但单帧最多补算 4 步，防止恢复页面后模拟爆炸；
- 重力初值约 `190～240 viewBox units/s²`；
- 最大下落速度约 `190～230 units/s`；
- 空气阻尼约 `0.995/step`；
- 碰撞恢复系数 `0.10～0.18`，只允许轻微弹跳；
- 切向摩擦 `0.82～0.90`，让表情落地后短距离滚动再停下；
- 角速度由接触切向速度产生并逐步衰减，旋转控制在自然的小角度范围。

每个固定步至少执行 4 次位置约束迭代：

1. 积分重力和速度；
2. 处理瓶口、左右曲面和椭圆瓶底约束；
3. 对所有已出生粒子执行圆—圆重叠检测；
4. 按质量相同原则沿碰撞法线各退一半，并修正法向/切向速度；
5. 再次处理瓶壁，避免粒子分离时被推出容器；
6. 速度和位移连续低于阈值约 300～450ms 后进入 sleep。

验收时必须出现真实可观测的接触事件：至少一枚后落表情先接触已落表情、改变横向轨迹或落点；仅检测“最终没有重叠”不算完成。

### 4.4 慢速自然节奏

以 8 枚表情为主要体验基准：

- 第一枚在瓶子进入视口后 200～300ms 出现；
- 相邻出生间隔 260～340ms，并加入由稳定种子产生的 ±30ms 微扰；
- 单枚从瓶口到首次接触约 1.35～1.9s；
- 首次接触后保留约 500～900ms 的轻弹、滚动和挤压调整；
- 8 枚从第一枚出现到全部休眠约 4.0～5.5s；
- 13～31 枚可每批 2 枚，但出生点必须分开，总时长控制在 5.5～7.0s；
- 32～62 枚可每批 3～4 枚，总时长最多约 8s，不能瞬间倾倒，也不能让用户等待十几秒。

运动必须由物理状态决定，禁止为每枚表情写相同的 bounce 关键帧。视觉层每帧只更新 `transform: translate3d(...) rotate(...)` 和必要的 opacity，不动画 top/left/width/height。

### 4.5 确定性与重播

- 随机性只来自稳定种子：`monthKey + entry.id + user_id + mood`；
- 同一个月、同一批记录重复播放得到相同总体堆叠，方便测试，也避免每次点击出现不可复现的穿模；
- 点击重播：增加 run token，立即取消旧 `requestAnimationFrame`，清空运动状态，重建模拟，从空瓶开始；
- 播放过程中快速连续点击 5 次，最终只能存在 1 个活动循环和 1 套节点；
- 切月、页面离开、组件 destroy、数据刷新都必须取消旧循环；
- 数据新增时只在当前月份和瓶子可见时按正确策略重建，不能让新旧物理世界叠加。

### 4.6 Reduced motion 与后台页面

- `prefers-reduced-motion: reduce` 时不运行下落或碰撞过程，直接使用同一求解器预计算的最终稳定布局；
- 点击瓶子只礼貌播报“已显示本月心情”，不产生位移动画；
- 页面不可见或瓶子离开视口时暂停渲染循环；重新可见后按真实经过时间安全续播，或在超出总时长时直接显示最终态；
- 不允许后台持续运行 60fps。

## 5. 性能预算

- 最大 62 枚粒子，圆—圆检测可先使用 O(n²)；每步最多 1,891 对，固定 4 次约束迭代仍需在目标手机预算内验证；
- 390×844 的 Chromium 模拟下，播放期间主线程长任务不得出现持续 >50ms 峰值；动画采样帧的 p95 间隔目标 <=25ms；
- 不在循环中调用 `getBoundingClientRect`、查询 DOM 或创建新节点；播放前一次性读取尺寸，循环只更新缓存节点的 transform；
- 轨迹/模拟结束后清理 rAF、临时数组、`will-change` 和 `aria-busy`；
- 如果 O(n²) 在 62 枚下超预算，再增加简单均匀网格 broad phase；不要预防性引入复杂空间索引。

## 6. 实施顺序

### 阶段 A：建立失败复现

1. 用确定性 fixture 创建 1 条根留言和至少 8 层链式回复，正文包含中文长句、连续英文和 URL。
2. 在 320×568、375×812、390×844 截取并测量当前评论行、正文和表单 bbox。
3. 新增失败断言：无横向溢出、深层正文宽度下限、表单全宽、触控尺寸、DOM 不递归嵌套。
4. 为 V2 现有固定槽位动画增加失败断言：发生粒子—粒子接触、接触改变轨迹、慢速总时长、重播只保留一个循环。

### 阶段 B：扁平留言线程

1. 新建 `comment-thread-domain.js` 并用单元测试跑通正常树、8 层链、孤儿、循环和重复 id。
2. 移动日记视图改为同级行渲染；桌面详情复用同一行模型。
3. 删除 `--comment-depth × margin` 旧实现和递归嵌套样式，不保留 fallback。
4. 修正手机评论网格、正文换行、操作按钮和表单宽度。

### 阶段 C：物理模拟最小闭环

1. 新建纯物理模块，先实现 1 枚粒子受重力落到椭圆瓶底并休眠。
2. 接入左右瓶壁和瓶肩，验证出生点无法穿墙。
3. 增加 2 枚圆—圆碰撞，验证后落粒子改变前一枚的位置/速度。
4. 扩展到 8、31、62 枚，调整约束迭代、摩擦和休眠阈值。

### 阶段 D：播放与生命周期

1. 用 rAF 播放物理状态，替换 V2 独立 WAAPI 下落关键帧。
2. 接入首次进视口、点击/键盘重播、播放中取消重启、切月和 destroy。
3. 完成 reduced-motion、页面后台暂停和状态播报。
4. 调整出生节奏，使 8 枚完整过程落在 4.0～5.5s，并在真机等效速度下人工确认“缓慢但不拖沓”。

### 阶段 E：全量门禁

1. 运行评论领域、物理领域和浏览器专项测试。
2. 运行完整 `pnpm test`、Axe 和构建预算。
3. 生成 320/375/390 手机深色截图、横屏截图、8/31/62 枚瓶子最终态和运动时间线证据。
4. 更新当前系统文档和规划状态，提交后交回主任务审计，不部署。

## 7. 自动化验收

### 7.1 留言领域测试

- 8 层回复输出 9 个同级行模型，顺序稳定且 logicalDepth 保留。
- DOM 中不得出现 `.photo-comment-thread .photo-comment-thread`。
- 循环 parent_id 不死循环，每条合法评论最多输出一次。
- 孤儿回复仍可显示，reply target 使用安全回退。
- 删除/新增回复后，当前回复目标和输入草稿行为保持正确。

### 7.2 留言浏览器测试

在 320、375、390、430px 和 844×390：

- 页面、列表、每条评论、表单均无横向滚动；
- 第 1 层与第 8 层正文左边界差值手机端 <=4px；
- 375px 下每层正文宽度 >=260px，320px 下 >=205px；
- 300 字中文、长英文和 URL 不越界；
- 回复/删除命中框 >=44×44px；
- textarea、回复状态条和发送按钮宽度不超过且基本填满评论内容区；
- 滚到底部后表单紧接评论列表，不出现由横向布局制造的大面积空白；
- 130% 字号下仍无一字一行和遮挡。

### 7.3 物理领域测试

- 相同种子运行两次，最终位置误差 <=0.01 viewBox 单位。
- 1 枚粒子落到底部、速度归零、未穿越边界。
- 2 枚同一路径粒子必须产生至少一次 contact，最终中心距 >=半径和减去 0.5 单位容差。
- 8/31/62 枚最终都位于瓶内，任意两枚重叠量 <=1 viewBox 单位。
- 后落粒子的接触会改变至少一枚既有粒子的 x、rotation 或最终槽位；禁止把固定预排坐标伪装成碰撞结果。
- 所有粒子在最大模拟时长内 sleep；没有 NaN、Infinity 或无限循环。
- 瓶壁、肩部和椭圆底部各有独立碰撞用例。

### 7.4 动画浏览器测试

- 8 枚第一枚延迟 200～300ms，相邻出生间隔处于规格范围，全部休眠约 4.0～5.5s。
- 运行时能观测到 circle-circle contact，且接触前后横向/旋转轨迹发生变化。
- 表情从瓶口安全区出生，整个外接圆始终位于瓶内可见区域。
- 连点瓶子 5 次后只有一个 rAF 链、62 个以内节点、一个 `aria-busy` 状态。
- Enter 和 Space 与点击行为一致，焦点不会丢失。
- reduced-motion 下活动 rAF 数为 0，最终布局立即可见。
- 页面切到后台、切月和关闭页面后活动循环为 0。
- 播放期间不读取布局；性能指标达到第 5 节预算。

## 8. 人工视觉验收

1. 打开含 8 条心情的月份，缓慢滚动到瓶子；观察表情从瓶口逐个出现，而不是从瓶身中间闪现。
2. 确认后落表情会撞到已落表情，发生轻微侧滑、滚动或推动，最后自然堆积。
3. 点击瓶子三次，其中一次在播放中途点击；每次都从空瓶重播，没有残影、重影或双倍速度。
4. 检查圆形和方形表情视觉形状保持正确，但碰撞都稳定。
